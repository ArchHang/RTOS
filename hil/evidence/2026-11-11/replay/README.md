# 宿主模型复跑

从仓库根目录用 Python 3 和宿主 GCC 运行。历史宿主为 x86_64 MinGW GCC 15.2.0。
输出目录须为新目录，运行结束后只留下编译输出、测试输出和 `summary.json`。

```powershell
python -B hil/evidence/2026-11-11/replay/run_host.py `
    --out-dir hil/logs/replay_20261111_host
```

`--cc` 可指定 GCC 路径，`--suite memory` 或 `--suite ordered` 可单独运行一个模型。
每个模型使用 O0、O2、O3、O2 + UBSan 四套配置。UBSan 遇到未定义行为时陷阱退出。
验收核对进程退出码、种子、每个种子的步数和配置间结果一致性，记录实际编译命令与源码摘要。

| 模型 | 使用的生产实现 | 判据 |
|---|---|---|
| `memory` | `rtos_heap.c`、`rtos_mempool.c` | 四个种子在堆和固定池上各执行 200,000 步。检查不重叠、数据哨兵、容量、分配/释放对账及完整复用。四套配置总计 640 万步 |
| `ordered` | `rtos_wait.c` | 独立账本核对四个种子各 200,000 步中的优先级顺序、同级 FIFO、邻接关系、位图、取消、重挂与唤醒对象。四套配置总计 320 万步 |

两个模型及内存端口桩保留原始源码字节。排序模型沿用独立的宿主类型桩，为编译当前
`rtos_wait.c` 补充 `is_mutex_wait` 字段。原始排序模型只运行 O0 和 O2 + UBSan 两套
配置，共 160 万步。复跑默认增加常规 O2 和 O3，保留原种子与每组步数。模型均为单线程，
采用宿主桩模拟端口或调度入口。实板 IRQ、缓存、栈帧和 RTOS 抢占由独立板测验证。
