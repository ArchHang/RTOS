# Loan channel 宿主模型与边界测试

本批次用于纯共享内存算法优化回归，复用 `channel_20261027` 最终宿主套件，
在独立目录保存当前批次证据。历史脚本和证据不做修改。

本目录测试链接真实的 `RTOS/IPC/rtos_channel.c`，不维护另一份通道实现。
`host_port.c` 仅提供原生编译所需的端口、任务和串行调度替身；生产源码没有宿主测试分支。

从工程根目录执行：

```powershell
python hil/channel_shared_20261027/host/run_host.py
```

默认使用本机 `C:\Users\23350\.conda\envs\mingw\Scripts\gcc.exe`。
其他环境可以通过 `--compiler <gcc路径>` 指定原生 GCC；`--out-dir` 可指定一个尚不存在的证据目录。
每次执行单独创建目录，保存实际编译命令、编译器版本、编译输出、运行日志、源文件标识和汇总。
开始和结束时的源码必须一致，否则整批运行拒绝判为通过。

## 执行矩阵

未优化基线保留原有六进程；优化版本的八个独立进程分别覆盖 `-O0`、`-O3` 下的四种测试：

| 测试 | 编译对象 | 检查内容 |
| --- | --- | --- |
| `model` | 真实生产 C、宿主端口、独立状态账本 | 每个容量 1、3、16 各进行 100,000 次确定性随机操作；每次比较状态守恒、累计计数、FIFO、有效字节、原始指针及保护字节 |
| `boundaries` | 测试翻译单元直接包含真实生产 C、宿主端口 | 独立进程内将私有实例计数放到 64 位极限，验证最后有效实例、最后有效票据对及拒绝回绕；没有导出生产测试接口 |
| `regions` | 测试翻译单元直接包含真实生产 C、独立线性区间账本 | 与有序生产索引不同的无序 oracle 检查半开区间、声明尾部、相邻与穿越、失败回滚、1000 次注销重排、私有表排序/数量/owner 和唤醒后旧调用 |
| `disabled` | 真实生产 C、关闭配置下的公共内联 API | 九个 API 均返回 DISABLED，输入、输出和对象保持不变 |

编译统一使用 `-std=c11 -Wall -Wextra -Werror`。启用用例显式打开通道，全部用例关闭断言，
从而验证非法 ISR 上下文在没有断言保护时仍返回错误。警告、非零退出、缺失完整日志、
不足 200,000 次模型操作或者源码在运行期间变化都会使驱动失败。

## 定向边界与生命周期

- 长度为零、完整块、超长提交、池耗尽、背压，以及非 8 字节整倍数块的 stride/padding。
- 重复提交、重复取消、重复归还、跨通道使用、旧 writer 冒充 reader、同地址重建后的旧票据。
- 不合法容量、尺寸、对齐、地址加法溢出，以及控制块、元数据、payload 和外部视图的重叠。
  重叠检查包含声明区域内尚未用于当前容量的尾部空间。
- 登记表用满、关闭后 drain/cancel/release、在途块导致 BUSY、资源全部归还后注销。
- 同时登记 8 个通道后，在最后一个登记项执行全部热 API，拒绝将输出写入其他通道的声明尾部。
- 合法最大容量 256：借满全部块、反向发布、按发布次序接收、持有全部只读块、反向归还，
  每阶段检查完整资源账本、FIFO、原始数据地址、序号、字节和保护区，最终关闭注销。
- 计数饱和、票据耗尽拒绝，失败视图逐字节不变，成功提交、取消、归还视图全部清零。
- 模拟优先级 0/4 的非法 ISR 与优先级 5 的合法 syscall ISR；同时检查错误前后的对象账本。
- 外部 BASEPRI、PRIMASK 和嵌套临界区中，确需阻塞时返回 SCHED 且不挂等待链；
  已有资源的非阻塞调用仍可完成。
- 跨 tick 回绕的总等待预算、连续虚假唤醒的剩余预算、关闭唤醒和同地址注销后重建。
- acquire/receive 分别验证提前唤醒但延后执行、资源晚到和恰好到期三个场景；
  超过有限预算时不授予租约，资源仍可由下一次调用取得。首次调用时已有资源仍可立即成功。
- Windows 下注销旧对象后释放元数据和数据，并将旧控制块页面设为 `PAGE_NOACCESS`；
  尚未返回的旧 receive 必须返回 DELETED，不能读取旧对象或改写输出。

另有活 descriptor 被应用覆写的契约演示：连续两次 acquire 使用同一 writer 输出，或者
连续两次 receive 使用同一 reader 输出，两次都能成功并占用两个块；通道不会猜测应用是否
已经在别处保存了前一个能力。因此遗失前一个能力会阻止关闭后的 deinit，返回 BUSY。
用例预先保留第一份能力副本，分别归还两块后才能成功注销。这验证应用必须管理能力生命周期，
不表示 API 能自动拒绝这种覆写，也不建议应用依赖该误用方式。

模型用自身枚举和 FIFO 保存预期状态，不以生产实现的链表构造预期结果。
保护字节覆盖控制块和元数据前后、payload 前后及每块 padding。另有一次故意破坏 payload
的阴性对照，必须由数据比较检测出来；这仅证明测试判定器有效，不表示通道自动提供 CRC。

## 结论的适用范围

这里验证的是原生 C 行为、能力票据、错误路径、尺寸和生命周期，不是 Cortex-M 仿真。
脚本等待回调只有一个假任务，不能替代真实 PendSV、优先级抢占、多任务并发、ISR 嵌套、
中断屏蔽时长、吞吐或 CPU cycle 测量；这些由本批实板 HIL 单独验证。

当前编译器环境没有可用的 ASan/UBSan 运行库，因此这些结果明确记录 `sanitizer=none`，
不声称执行过内存或未定义行为 sanitizer。Canary 和保护页各自只检测覆盖到的内存访问。
裸指针越界、租约失效后直接读写、DMA 完成与否、总线可达性和 M7 缓存一致性仍属于应用契约，
不能由本测试或此 API 自动保证。确定性随机及边界测试提高了已知风险的覆盖，不能证明没有所有未知缺陷。

构建二进制位于被忽略的 `.build/`；正式结果以最新一次 `summary.json` 为准，
仅有部分进程日志而没有通过汇总的目录不表示整批通过。

`evidence/baseline_pre_optimization/` 是生产 C 尚未修改时的原六进程基线，
`regions` 仅在新索引冻结后加入；比较时应分别说明原有回归与新增覆盖，不能把新增白盒
用例声称为在旧实现上运行过。新专项通过公共 API 施加操作，私有读取仅用于校验
`channel_regions` 的严格有序、不重叠、每个活跃 owner 恰好三段与完整声明边界。
Windows 保护页用例还在阻塞调用已被唤醒后注销控制块、重排其他 owner 的索引，
使旧控制块不可访问；旧调用必须只依赖已保存的地址/实例号返回 DELETED。
