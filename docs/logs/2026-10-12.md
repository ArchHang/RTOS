## 源码审计与缺陷修复

当时完整阅读 RTOS 下 61 个 C/H 文件，再核对设计与测试夹具。原 selftest 为
431 PASS、0 FAIL、11 INFO，但第一批新增 64 个断言得到 23 PASS、41 FAIL。
失败断言数不等于独立 BUG 数；原有测试全部通过没有覆盖这些窗口。

| 范围 | 触发条件与原问题 | 当日修改 |
|---|---|---|
| 调度状态 | 启动前 suspend/resume、嵌套挂起、挂起期间 yield，以及失效切换候选 | 保护启动状态，维护嵌套层数，提交前检查候选，取消切换时恢复当前任务 RUNNING |
| 任务生命周期 | 创建后先被抢占、返回句柄尚未发布；静态 TCB 构造期间被操作；无效句柄及 idle 操作 | 句柄先于 READY 发布；预留身份及 INITIALIZING 状态；按登记地址验证任务，保护 idle |
| 等待归属 | event 超时后重读已复用对象；同优先级重排破坏 FIFO；活跃 IPC 重初始化 | 超时解绑前保存结果；有效优先级不变时不重排；拒绝使用中对象重新初始化 |
| 队列 | 容量乘法溢出、直达传递节点长度不匹配 | 增加算术检查；拒绝无效等待节点，继续寻找合法等待者 |
| 内存池 | 接受块内地址、重复 free、对齐或容量溢出 | 检查块起点及算术边界，扫描空闲链拒绝重复释放；4 块池不再出现 free_count=5 |
| 定时器 | 回调重启破坏到期链；同址重建后旧 DELETE 生效；相对回调结束续期造成漂移 | 每次处理一个到期对象；异步命令携带 generation；按原到期相位续期并跳过错过周期 |
| 定时器上下文 | ISR 打断 TIMER 被误认为服务任务；重复初始化先清活跃链 | 直接命令要求线程上下文；重初始化先拒绝，保留现有定时器 |
| 端口 | 临界区削弱更强屏蔽；合法 IRQ 在 PendSV 提交窗口改变候选 | 使用 BASEPRI_MAX，保存/恢复原 mask；保护从任务提交到安装 PSP 的窗口 |
| USB/OSAL | 超时预算、RESET 完成混淆、线程池泄漏、异步 timer 删除失败仍释放资源 | 总预算、会话代次及完成序号；按真实任务状态回收；失败保留资源，忙槽继续扫描 |
| CherryUSB | 接口/alt/config 越界、MSC LUN/扇区溢出、DWC2 超长包越界写 | 先检查索引和范围；约束描述符扫描；超出请求容量的数据丢弃并 stall，保持尾部 guard |

另修正毫秒换 tick 的 32 位乘法溢出、MSC 线程栈 bytes/words、EXC_RETURN 注释和
特殊异常优先级查询边界。关闭热路径统计时 CPU=0、idle=10000 为约定占位值，
不表示实测 CPU 空闲。内存池 free 的重复归还检测为 O(n)，没有缓冲区长度参数，
存储容量仍由调用方保证；对象 generation 也不延长其外部存储寿命。

当时最终专项为 117 PASS/0 FAIL，三次独立复位；selftest 为 432 PASS/0 FAIL/10 INFO，
boundary 为 103/0，BM0–BM7 与 S1–S5 完成。PRIMASK 在这一阶段仅有 13 单元编译检查。
日常构建恢复后重新下载并观察 15 秒，不是长期可靠性证明。

测试器也曾出错：固定次数提交未必填满 timer 命令队列，最终必须在真实 IRQ 中提交到
ERR_TIMEOUT；寄存器影子的 FIFO 范围不足曾令夹具自身失败；闲置 mutex 重复 init
曾被补丁过度拒绝，原 selftest 检出后恢复兼容语义。内存池重复 free 从旧 INFO 改为
要求 ERR_ALREADY 的 PASS，因此 selftest 从 431/11 变为 432/10，不能视为新增一个场景。

## 第一阶段性能试验

最终保留临界区嵌套计数的局部快照及 mutex 有序等待队首计算；调度选择 helper 和
对齐候选撤回。当时仍是直接继承实现，后来的全图继承修复见[10 月 26 日](2026-10-26.md#adversarial)，
不能把这里的队首计算成本当作当前完整 PI 成本。

| 指标，CPU cycle | 阶段基线 | 最终保留组合 | 限定条件 |
|---|---:|---:|---|
| 临界区对 | 30 | 24 | 当时的端口，后续事务加固已改变成本 |
| mutex，4/8 等待者 | 71/107 | 46/46 | 局部计算，不是全路径常数时间 |
| perf 信号量往返 | 1395 | 1607 | 实际退步 15.20% |
| 普通 bench 信号量往返 | 1393 | 1394 | 与扩展 perf 夹具布局不同 |
| 普通 bench ISR 唤醒平均 | 546 | 552 | 实际退步 1.10% |

每阶段三次独立复位；最终另执行 audit 117×3、selftest 432/0/10 INFO、boundary 103/0
及 S1–S5。S1 未形成稳定 PI 争用，S2 的 threshold=0 关闭了超阈值计数，status=0 或
bad=0 不证明满足业务 deadline。较早 combined 通过功能测试，但普通 bench 往返
由 1393 增至 1654，因此未保留调度 helper。带旧时间戳的快照曾复用旧对象，
该 baseline_bench 被判无效；后续强制刷新相关对象，不能引用无效镜像的性能值。

<a id="lowlevel"></a>
## 低层与汇编优化

随后保留内部调度提交返回 TCB，由 PendSV 从 R0 使用返回指针，公共 void 入口保持；
正常分支直接返回 next，信号量恢复复用本任务指针，摘链前快照 next/prev，入口复用
ISR 状态并保留优先级 guard。未扩大 TCB 或等待节点，不删除原 mask 保存、PSP 恢复
窗口、MSP 对齐或 S16–S31 保护。编译出的两条 LDR 减少、信号量序言保存量 32→24 B
只描述该构建，不能换算成每条指令固定耗时或所有任务栈统一减少 8 B。

| 第二阶段指标，CPU cycle | 本阶段基线 | 保留组合 |
|---|---:|---:|
| perf 信号量往返 | 1607 | 1296 |
| 普通 bench 信号量往返 | 1394 | 1307 |
| yield，perf/bench | 234/235 | 229/229 |
| 普通 bench 创建/删除 | 6121 | 6137 |
| 普通 bench queue 唤醒最大观测值 | 774 | 795 |

当时最终 audit 117×3、selftest 432/0/10 INFO、boundary 103/0；默认与 HOTPATH_STATS=1
各三次上下文检查，每次 LC 24/0、PC 22/0。两个 FPU 任务各 10000 轮比较实际
S16–S31 位模式，另有整数 peer；不在每轮重装期望值，仍不代表穷尽所有浮点异常。
7 配置×13 单元、91 项严格 ARM 编译通过；额外五种配置此阶段未上板。

60 次下载采集中只有 57 次正常完成，另 3 次为动态诊断失败及其现场核验，不能写为
60 次全 PASS。同 ELF 静态回调的 Flash 指令缓存 ON/OFF/ON 对照为 1229/1750/1229
cycle，三次复位均完成且恢复 ACR；它证明该镜像受缓存开关影响，不解释所有布局差异。
首次动态诊断因 heap_free 28496→28488 而失败；HOTPLUG 读到相邻空闲块及两个头部，
与仅向后合并造成额外 8 B 元数据一致，不能将差额直接称为失联泄漏。先前 Under Reset
探针重置了现场，其 RAM 读数作废。日常 data/bss 不变，text 相对前阶段增加 60 B。

<a id="stress-method"></a>
## 综合压力方法与验证限制

压力设计借鉴 [FreeRTOS IntQueue](https://github.com/FreeRTOS/FreeRTOS/blob/main/FreeRTOS/Demo/Common/Minimal/IntQueue.c)
的消息身份和实际并发条件，以及 [Zephyr Ztress](https://docs.zephyrproject.org/latest/develop/test/ztest.html#stress-test-framework)
的多优先级、可变交错与最低覆盖次数。执行结果按实际完成日期归入[10 月 13 日](2026-10-13.md#production-stress)。

核心判据为成功接纳消息的来源/序号/内容守恒、每个角色独立进展、实际阻塞与真实 IRQ
嵌套、令牌守恒、过载拒收计数，以及停止生产→排空→停止消费者→销毁对象的有界顺序。
多消费者完成次序可以不同于出队次序；event 的逐等待者即时 CLEAR 不能照搬广播快照。
负向对照只损坏一条消息，由正常检查发现，不能预置 FAIL 计数。

这些阶段没有验证物理 USB 主机枚举/传输、真实传感器或 DMA 总线、任意生命周期交错、
M7 缓存一致性、所有配置组合及硬实时 WCET。USB 寄存器影子与协议注入是板上逻辑测试。
观测最大值、三次相同输出、长期不崩溃都不足以证明任意输入无缺陷。当前复现方法见
[HIL 入口](../../hil/README.md)，测量口径见[性能参考](../rtos_performance_report.md)。
