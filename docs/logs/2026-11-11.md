## MSP 异常的复现与修复

默认 F446 启动向量直接引用端口函数。旧版按默认路由以 `-O0` 烧录，
32 轮延时前后 MSP 都为 `0x2001FFA0`，因此普通日常镜像不触发这条包装缺陷。
用 `robustness_msp -UseVectorWrappers -Optimization O0` 选择旧 BSP 的 C 包装后，
实际 ELF 两个入口均先执行 `push {r7}` 和 `add r7, sp, #0`，再尾跳到端口。
包装没有机会出栈。PendSV 还会保存已经被改写的 R7，`-O0` 下它可作为任务帧指针。

| 同一夹具 | 首任务 MSP | 单次探针 PendSV 后 | 32 轮延时 |
|---|---|---|---|
| 旧包装 | `0x2001FF9C` | `0x2001FF98` | 在正常切换路径触发故障，未收到结束行 |
| 修复包装 | `0x2001FFA0` | `0x2001FFA0` | 32 tick，MSP 未变，4 项通过 |

两个 C 包装改用 naked 声明，并保留原来的汇编尾跳。修复版 ELF 入口没有 C 序言，
直接向量路由仍是默认值。探针独立保存恢复 R7，使旧版能在正常切换故障前留下
单次 MSP 变化。一次早期复现尝试在探针加入前已故障，原始日志仍保留。第一次编译
因测试夹具写错 tick 查询符号而失败，修正后再上板，该失败归属夹具。
最终用 GNU 汇编器条件指令选择测试向量。重建的包装镜像与实测镜像的 Flash 加载字节
一致，默认向量和复位代码的段字节与重定位也一致。

## 修复与直接证据

| 缺陷 | 修复行为 | 定向回归 |
|---|---|---|
| 调用方屏蔽 PendSV 时，需阻塞的接口可以先返回成功 | 进入实际等待前核对临界区深度及保存/实时屏蔽，拒绝会失去切换机会的等待 | BASEPRI、PRIMASK、FAULTMASK、嵌套临界区各有复现；可立即取资源仍成功，解除屏蔽后实际超时 |
| 静态创建可覆盖另一任务的栈；实际栈底字被改写未报警 | 构造期一起保留 TCB 和栈范围；方法 2 在 idle 检查实际栈底字，和水印使用同一填充值 | 拒绝重叠、接纳相邻；只改物理栈底字并等待钩子 |
| 协作配置在 Tick 抢占应用任务，主动让出也可能漏选更高优先级任务 | Tick 仍维护时间和到期任务；正在运行的应用主动让出或阻塞时重新选取，idle 可被替换 | 跨真实 Tick 核对不抢占；用新任务单独验证主动让出的选取和执行 |
| 动态任务创建在堆压力下误报 `RTOS_ERR_PARAM` | 预检只核对配置容量与算术边界；实际分配失败为 `RTOS_ERR_NO_MEM`，回收已取得的 TCB | 堆尾容得下 TCB 但容不下任务栈，输出指针不变，分配/释放及容量符合回滚预期 |
| 空闲堆块相邻但不能共同满足合法请求 | 单块不够时查连续空闲段，满足请求才合并；最大容量查询使用相同段语义 | 相邻块可重用，跨在用块的请求失败，所有分配释放后可恢复整段容量 |
| 非对齐的堆内地址可能被当作块头；固定池在 64 位 ABI 步长仍按 4 字节对齐 | 堆先做整数地址范围与对齐校验；池按空闲节点的实际 ABI 对齐 | F446 地址/池边界检查；64 位宿主两个对齐陷阱旧版触发、修复后正常退出 |
| USB OSAL 重复初始化重置活跃对象和分配 | 初始化成功后拒绝重复初始化并保留活跃资源 | 信号量仍可消费，原缓冲内容保持，第二次分配不会重发活跃块 |
| 热点统计查询漏计当前任务尚未切出的片段 | 用同一时刻补计运行片段，查询与统计窗口一致 | 任务没有切换时，运行周期和 CPU 占比仍反映已执行片段 |
| CDC 数据后追加零长度包失败，写者空等且后续写入失效 | 终结该块，唤醒写者并保存失败结果，保留已成功完成的字节计数 | 真实定时器 IRQ 调用完成逻辑，替身拒绝 ZLP；写入提前返回、下一次发送完成 |
| USB IRQ 分发读取旧回调和新参数 | 在有界临界区获取同一代配对，离开临界区后执行回调 | 真实两级 EXTI IRQ 在读取窗口注入重新注册，当前回调保留旧参数，下一次使用新配对 |

## 性能与验证边界

- 调用屏蔽检查放在实际阻塞和需要切换的分支。动态创建省去一次堆最大块扫描。
  静态任务创建在既有登记表遍历中增加范围判断。运行期默认抢占配置保留就绪位图。
- 堆的普通单块命中无需向后查找，释放最多合并一个相邻块。合并慢路在同一临界区
  验证并提交，最坏仍为 O(N)，N 为物理块数。没有为此增加每块头大小。
- 性能监视新增结算位于查询或窗口操作，默认热点统计仍关闭。USB 分发持锁时间
  由固定表长限定，回调在退出临界区后执行。
- USB 端点替身与真实 NVIC 交错证明软件路径行为。物理 USB 枚举、总线传输、
  真机主机和 DMA 互操作需要独立硬件验证。Cortex-M7 实板、Cache 行为、超长运行、

- 源码复核发现的后续风险包括 SysTick 24 位重载越界的配置检查、idle 栈告警钩子的
  TCB 借用寿命，以及 USB 断连多读者、MSC 队列资源不足和非二次幂 CDC 环形容量
  的回绕。尚无本轮端到端复现或修复验证。接口职责和调用限制详见
  [设计手册](../rtos_design.md)和[公共 API 契约](../ai/README.md)。

## 实板项目驱动的全链路优化

以本日上一阶段已验证工作树为基线。在 NUCLEO-F446RE 上通过 ST-LINK VCP/COM3
运行真实 USART2 接收、协议解析、队列交接、1D-CNN 推理和回包。应用保留于独立
`uart_pipeline` 构建变体，主机经串口发送完整的 2044 字节量化输入。每个合法响应
核对 ID、CRC、类别和四个 logits，独立本机 GCC DLL 使用仓库现有 C 源和权重。
同一套帧流在 115200、460800、921600 均完成了基线。该比对用于证明集成正确性，
没有使用麦克风或真实语音分类数据集。

**从项目发现的优化点。** 逐字节输入使通用队列的动态长度拷贝和重复读取 ISR 状态
成为常见开销。单字节路径改为字符读写，其余长度保持通用拷贝。发送／接收复用
ISR 状态快照，保留初始化复查、等待和临界区契约。独立 A/B 的构建输入只有
`rtos_queue.c` 一处不同。在 921600 的遥测窗口 8 下，ISR 从 550.91 降至
495.62 周期/字节，约节省 10%。同口径 CNN 窗口 4 为 7.88→7.92 帧/秒，
说明模型阶段仍限制整链吞吐。日常 O2 镜像 `text` 增加 148 B，`data` 和
`bss` 持平。[性能对照](../rtos_performance_report.md#8-实际-usart2-与-cnn-应用)

**项目自身的故障与修复。** 旧版在 921600 接收非法的短遥测头时，误把紧跟的合法帧
算入 2044 字节负载，直到空闲超时后才恢复。现在收到完整头便核对操作码允许的长度。
坏 CRC 和非法长度各用一条连续合法请求验证恢复。UART 原始处理区分硬件异常与
软件队列溢出，错误时唤醒空队列解析者；未人为制造硬件溢出或线缆故障。累计 ISR、
解析及模型 DWT 周期提升到 64 位，避免长窗口的 32 位回绕。

| F446 验证 | 实测 |
|---|---|
| 应用持续推理 | 921600、窗口 4、320 次、40.36 秒，最大 logit 绝对误差 0，无正常流量丢帧、拒绝或 UART 错误 |
| 计数器 | 320 次模型累计 6,756,038,081 周期，超过 `2^32`，主机正确读取高位 |
| 过载及恢复 | 12 次推理突发中 4 次完成、8 次显式 BUSY；主机逐 ID 对账，过载后首条遥测正常 |
| 队列专门回归 | O0、O2、PRIMASK 且关闭断言的 O3 各 6/6，覆盖 1/5 字节、非对齐、回绕、实际阻塞双方 |
| 既有回归 | 销毁窗口 80/80，混合等待 1600/1600，边界 103/103，BASEPRI 阻塞 516/516 |
| 生产型压力 | 20 秒，165/165。44,007 条已接纳消息逐条守恒，屏蔽泄漏和截止期违约为 0 |
| 两款芯片编译 | F446 与实际 H743 CMSIS 各 19 组示例及 RTOS 部分链接，通过；H743 未做本轮实板 |

模型 O2/O3 都在关闭浮点收缩的条件下通过精确数值核对，O3 选入持续运行。它的
单次吞吐差异只有约 0.3%，当前证据不足以把差异归因于编译优化。其他业务、长时间
供电和全局最坏延迟需独立测量，短负载内的无错不构成长期可靠性保证。

复验见 [HIL 项目入口](../../hil/README.md#43-串口遥测与-cnn-项目)。本机
`hil/logs/uart_project_20261111/` 保留应用输入身份、原始二进制收发、逐请求耗时、
镜像、Flash 校验和独立复核。回归后重新下载日常固件并由串口确认任务持续运行。

**取舍。** 对照设计手册的调度、等待、端口、IPC、内存、定时器、观测和 USB 章节，

- **互斥锁最终释放。** 原实现对空等待链也调用唤醒和全图继承重算。现在在原临界区
  内判断等待链为空后清除所有者及交接标记。该锁没有捐赠边，从其他锁得到的继承

  重算。O2 下 8 把锁、16 个同 tick 信号量到期，平均为 4142 → 3343 周期。
- **固定块池试验撤回。** 2 的幂块长使用掩码验证可小幅改善 O2/O3，但 O0 的

  起点，已有溢出、重叠和重复归还保护保留。保留夹具、差异和实测记录以供复验。

## F446 长时并发与回绕回归

**范围。** NUCLEO-F446RE 通过 ST-LINK 下载，使用 COM3 采集。综合场景运行 16 个
任务，优先级 5 至 20，六路消息来源同时使用队列、信号量、事件、通知和互斥锁，
三层 IRQ 由目标板真实执行。每次长测包含正常负载、主动过载和恢复三个阶段。
验收对照六路消息的序号与校验和、信号量账本、IRQ 入口账本、控制截止、屏蔽恢复及堆水位。

### 问题复现与修改

| 问题 | 同一 F446 夹具的原版观测 | 修改与复验 |
|---|---|---|
| USB OSAL 临时让步固化了互斥锁捐赠优先级 | 持锁任务的基础值为 9，等待者捐赠 4。让步后基础值错误地变为 4，释放后有效值仍为 4，两项断言失败 | 保存并恢复基础值，继续由内核计算继承。BASEPRI/O2 和 PRIMASK/O0 关闭断言分别通过 9 项，释放后回到 9 |
| USB CDC 非二次幂接收缓冲错读 | 合法的 768 字节环从 `UINT32_MAX-3` 接纳 8 字节，分两次读取时后 4 字节是 `00000000`，应为 `8596A7B8` | 非二次幂容量使用环内位置与环形距离，默认二次幂容量保留掩码定位。768 字节 BASEPRI/O2 和 512 字节 PRIMASK/O3 关闭断言各通过 4 项，包含跨末尾、满载字节顺序和清空 |

新增 `wrap_ipc_regression`。每轮在延时链空闲时预置 Tick 为 `UINT32_MAX-32`，再由
硬件 SysTick 递增。Tick 0 先处理到期摘链，再挂起由 NVIC 执行的 EXTI1。每轮 12 个
任务同时等待信号量、队列收发、事件、任务通知和互斥锁，检查同刻超时与完成各自只结算
一次、迟到通知保留、优先级继承回退、对象等待链和位图清理。BASEPRI/O0、BASEPRI/O2、
PRIMASK/O3 关闭断言均通过 16 轮，共 576 次任务等待。
