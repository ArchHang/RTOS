# 2026-11-12 RTOS 更新日志

<a id="heap-size-bins"></a>
## 通用堆分桶后端

原堆在临界区内从低地址扫描物理块。堆中有大量已用块和小孔时，即使还有足够大的空闲块，
也可能要扫描很久。新增后端借鉴分离适配与位图索引，将空闲块按实际大小分类。释放时立即
合并左右空闲块，拆分出的尾块也立刻加入对应桶。所有桶共享原有静态堆区，避免固定档位
长期预留互相无法使用的容量。[TLSF 论文](https://pure.york.ac.uk/portal/en/publications/implementation-of-a-constant-time-dynamic-storage-allocator/) ·
[Zephyr sys_heap](https://docs.zephyrproject.org/latest/kernel/memory_management/heap.html)

两种后端共用公共 API 和原有容量设置。分桶模式保留 8 B 块头、8 B 对齐、24 B 合法堆下限
和 24 B 拆分尾块门槛。链表链接放入空闲载荷，默认 32 KiB 配置的桶索引占 108 B。
移动或合并前先校验当前块边界、待摘链和目标桶头。已回收的块头立即计入空闲载荷；
申请失败时保留计数和布局。宽桶可能遍历桶内候选，最大块查询返回真实容量。

F446 同夹具 O2 测得，128 个小孔场景的 1,024 B 申请平均由 10,476 降至 889 周期，
少块申请由 377 增至 889 周期，少块归还由 174 增至 1,011 周期。
因此 `RTOS_CONFIG_HEAP_USE_SIZE_BINS` 默认 0，碎片场景分配延迟敏感的应用可设为 1。
同一 O2 夹具链接的 `text` 增 1,564 B，`bss` 增 104 B，`data` 相同。
按场景选择实现和验证时使用工程配置统一重编译。[完整对照](../rtos_performance_report.md#f446-heap-size-bins)

F446 O0、O2、O3 两个后端的定向夹具均通过 6 项。分桶模式另通过通用健壮性 52 项、
回收抢占 3 项和真实 TIM6 下 O3/LTO 堆计数 4 项。60 秒生命周期完成 18,368 轮、
147,067 次任务创建和 165,638 条消息对账，最大可申请空间与空闲字节均回到 28,496 B。
180 秒业务压力逐条核对 392,418 条消息，165 项通过，1,331,679 次屏蔽检查零泄漏，
控制响应最多 1 Tick 且零超期。

宿主按 32 KiB、512 KiB、1 MiB 各跑 O0/O2/O3/O2+UBSan，内存模型共 1,920 万步，
其中通用堆 960 万步，固定池 960 万步。1 MiB 有向探针复用两个超出 16 位编码范围的块。
10 个小容量配置、宿主 LTO 观察、F446/H743 各 20 组严格编译和部分链接通过。
H743 分桶镜像完成链接及向量检查，H743 硬件尚未执行本轮用例。

实测使用隔离构建。F446 原固件完整 512 KiB 读回与两次测试前备份逐字节一致，
14 个选项字段一致。本机日志、ELF、映射、验证器和备份位于
`hil/logs/f446_heap_20261112/`，最终核验结果为该目录的 `verified.json`。
可重建的隔离构建目录和重复 ELF 已清理，保留源码快照及每个镜像的一份 ELF 和映射。

## 降低分桶堆少块开销

冻结上一版分桶实现并重测。少块探针与碎片探针都反复从尾部大空闲块拆分，释放时
合并右邻。O2 反汇编显示，在这条路径中，候选和相邻块信息会被重复校验，源/目标桶
号也会在预检与提交分别计算。拆分或单侧合并后经常仍落在原单例桶，旧路径仍执行
摘除和重新插入。

最终版在同一临界区复用候选和邻块信息。精确桶命中以完整大小字确认块长和空闲位，
校验边界和链接后直接摘除。宽桶保持首个足够大的块选择顺序。同桶单例允许直接替换
桶头，跨桶、多个节点和双侧合并仍先核对相关链接与物理边界，再提交变更。
普通释放在尺寸和位置不变时保留已经核对的后继标签。块头和静态索引容量保持原规格。

三种实现使用同一扩展夹具。新增 32 B 小孔原址复用和 4 KiB 跨桶拆分，核对容量和守卫，
然后各测 256 次。O2 下，少块申请 888 → 590 周期，归还 1,012 → 569；128 个小孔后的
申请 889 → 590，线性堆为 10,474 周期；32 B 申请/归还 632/633 → 480/521。
第一次改动只复用校验和桶首，32 B 申请仍有退步，最终版因此增加精确桶专用路径。
4 KiB 跨桶申请在 O0、O3 分别增加 153、32 周期，O2 减少 10 周期。
O2 整体镜像 `text` 比旧分桶版多 804 B，`data`、`bss` 相同。
[同板性能对照](../rtos_performance_report.md#f446-heap-bin-fast-path)

最终版和两个对照版的 O0/O2/O3 扩展夹具各通过 8 项，逐条核对容量、计时汇总和镜像身份。
最终版通过通用健壮性 52 项、回收抢占 3 项、真实 TIM6 的 O3/LTO 统计 4 项。
60 秒生命周期完成 18,371 轮、147,091 次任务创建及 165,675 条消息，空闲与最大可分配
块均恢复到 28,496 B。180 秒并发压力对账 392,422 条消息，165 项通过，
1,331,677 次屏蔽检查无泄漏，控制响应最多 1 Tick，零超期。

宿主 32 KiB、512 KiB、1 MiB 各执行四种优化/检查配置，共 1,920 万模型步。
同容量的结果与冻结版逐字节一致。最小堆、宽链高地址、宿主 LTO 均通过。
F446/H743 各 20 组严格编译及部分链接通过，H743 本轮的验证范围为交叉编译。
F446 全部 512 KiB Flash 恢复后与两份测试前备份一致，14 个选项字段一致。

本机批次位于 `hil/logs/f446_heap_fast_20261112/`。保留了两次迭代、所有串口、
反汇编、源码快照、单份 ELF、链接映射和恢复记录，最终核验见 `verified.json`。

## 自适应堆与实际工作负载采样

F446 使用冻结分桶采样镜像分开统计启动与业务。三项启动窗口均记录 148 B 和 4,096 B
各一次申请。真实 ADC/DMA 固定池业务和 16 任务的 30 秒并发采样均无运行期通用堆申请。
60 秒生命周期捕获 294,178 次申请，成功 294,172 次并全部释放，32 B 请求为零。
99.998% 的申请发生时只有一个物理空闲块。9,223 次释放把空闲块数从四增至五。
据此，同一堆在五个空闲块以内使用偏移小表，第六块触发分桶，降至两块时恢复小表。
桶宽沿用现有分类，当前数据不支持预留 32 B 专用容量。

两种索引共用物理边界、8 B 块头和容量账本。拆分保留空闲块数，整块分配减一，释放
按零、单侧、双侧合并分别加一、不变、减一。切换先核对索引，再发布新表示。首轮实测
发现 32 B 精确分配退步，以及编译器将复杂桶路径展开到公共释放入口。最终逆向检查
小表、只为选中块校验前驱标签，将分桶释放与建桶拆成独立调用。窄配置编译中还发现
建桶函数复用合并写入引起 GCC 的数组边界诊断。改为只接收本次孤立释放的偏移和长度后，
小堆编译、账本及 LTO 回归均通过。

同板 O2 少块释放 568 → 478 周期，TCB/栈释放分别为 505 → 352 和 759 → 457。
碎片场景 1 KiB 申请 590 → 621 周期，线性堆为 10,476 周期。32 B 申请从首轮
自适应版 570 降至 491，冻结分桶是 478。最终版的释放仍慢于对应的线性堆。
32 KiB 的 O2 镜像相对冻结分桶增加 16 B `bss` 和 1,720 B `text`。
同一宽桶的 128 个不足候选用例观察到 9,371 周期拒绝和 10,000 周期最大块查询。
以上为实际 API 观测值。

最终版 F446 生命周期完成 147,091 次动态创建及 165,674 条消息对账，恢复 28,496 B
空闲和最大容量。180 秒压力通过 165 项，核对 392,672 条消息及 1,332,248 次中断屏蔽
检查。真实 ADC、真实 TIM6/LTO、通用健壮性和 9 项容量切换回归全部通过。宿主模型
覆盖三种堆容量和四种构建，F446/H743 交叉编译与部分链接通过。

本地批次为 `hil/logs/f446_heap_hybrid_20261112/`。三个独立采样摘要位于
`profile_tool/verified_profile_*.json`。同板对照、最终用例与恢复核验汇总在
`verified.json`，每个镜像保留一份 ELF、映射、构建记录和原始串口。最终烧录源码的
选块条件运算符之后只做了等行数换行调整，验证器逐文本核对该唯一差异。
F446 原固件的完整 512 KiB 读回与双备份一致，14 个选项字段一致。

## 线性堆搜索检查点

按地址 first-fit 在连续申请时重复遍历低地址在用块和不足小孔。默认后端增加两个
32 位值，记录上次成功分配的起点和前缀的最大连续空闲段。只有前缀确定放不下本次
请求，才跳过它。低地址块成功释放时使检查点失效。原 8 B 块头、对齐、前向释放
合并、分配时连续段合并和统计公式保留。

F446 同夹具 O2 少块申请 378 → 217 周期，128 小孔的 1 KiB 重复申请
10,474 → 233 周期。少块释放 174 → 217 周期，首轮检查点版为 239 周期。
最终失效检查放在释放合法性检查之后、合并之前。交错 TCB 申请 285 → 330 周期。
整镜像增加 132 B `text`、8 B `bss`，`data` 相同。失效后的冷扫描仍为线性复杂度。

O0、O2、O3 的八项定向夹具通过。60 秒生命周期对账 147,091 次动态创建及
165,650 条消息，最大可申请载荷回到 28,496 B，仍有 2 项入口活跃分配。原始
空闲载荷为 28,352 B，差值 144 B 来自默认后端保留的 18 个可在后续分配中吸收的
块头。通用健壮性 52 项通过，定向宿主检查和随机模型的旧版及新版输出一致。
F446 原固件的完整读回与双备份一致，14 个选项字段一致。

同板 ELF 和映射、原始串口、宿主定向用例、`verified.json` 及恢复记录。

## 交错释放、检查点失效与释放路径精简

默认线性堆在合法的低地址释放时只清零检查点偏移，下一次从堆首扫描时忽略旧前缀
上限。释放只处理已验证的唯一右邻，清除被吸收头并统一更新一次本块长度。合并回收
的 8 B 计回原容量账本。块头与状态占用不变。

F446 同板三版对照。O2 原少块夹具释放为 175 / 236 / 177 周期，对应原线性、上轮
检查点和精简版，测试镜像 `text` 为 43,864 / 43,996 / 43,956 B。新混合夹具
交错轮换请求尺寸，少块和 24 活跃块分别有 128、192 次低地址释放。
24 活跃块用例的全部申请为 979 / 762 / 750 周期，失效后首次申请为 744 / 814 /
789，全部释放为 222 / 225 / 220。20 秒动态任务的成功申请为 444 / 247 / 262，
非空释放为 169 / 184 / 175。三版任务轮数近似，原线性 6,178，两种检查点各 6,179。

三种优化等级的对照通过。宿主定向模型逐次验证选块地址，移除低地址失效动作的
隔离负对照在四种构建中均触发 first-fit 错误。最终版的无包装 60 秒生命周期完成
147,091 次任务创建、165,651 条消息对账，并恢复 28,496 B 最大连续载荷。
F446 原固件 512 KiB 读回与双备份一致，14 个选项字段一致。

## 默认线性堆左合并可行性

<a id="heap-index"></a>
## 空闲索引与释放分支的板上评估

在独立快照中实现 532 B 精确位图、144 B 和 72 B 分段索引。512 次混合申请
的块头访问由 2,863 降到 1,034、1,290 和 1,762。相同 F446 O2 夹具中，
完整申请均值由 304.47 升到 445.29、432.98 和 473.70 周期。借还操作
持续承担索引查找和更新，生产堆继续采用当前检查点扫描。

六种 O(1) 释放候选完成正反顺序对照。最佳 O3 原混合释放由 137.45 降到
125.89 周期，该候选的 O2 C 库夹具混合申请由 304.47 升到 322.88。
完整 ELF 的机器码、字面量和调用窗口已核对，现有静态证据不能独立分解前序执行
状态与链接布局的影响。各候选的收益和退步一并保留。

十个版本各通过 28 个宿主构建与运行组合，包含四种优化或检查配置的 first-fit
模型、跨区合并压力、小堆及高地址边界。F446 最终保留版本复跑多优化级、
七项屏蔽交互、52 项通用健壮性及 60 秒生命周期。

本批 115 份板上采集和六次完整恢复通过核对。生命周期完成 147,091 次动态
任务创建、165,650 条消息、150,015 次 IRQ 和 18,751 次嵌套中断，最低
空闲载荷 616 B，结束时最大连续载荷恢复到 28,496 B。

本机证据位于 `hil/logs/f446_heap_index_20261112/`。`reference/` 保存基线和
候选内核，`fixtures/` 保存冻结夹具与独立计数夹具，`directed/run.py` 可重跑
宿主模型。`build_diagnosis.ps1` 与 `run_suite.ps1` 记录板上配置和采集顺序，
`images/` 保存 ELF、映射及构建参数，`analysis/` 保存反汇编与布局核对。
原始串口、各批恢复回读及 `verify_index.py` 保留在同一批次。

清理 14 个独立构建目录与 115 份重复下载 ELF，共 876,687,652 B。构建时的
内核和最后一份载荷源文件归档到 `snapshots/`，每份实测 ELF、映射、构建参数及
串口仍在原位置。清理后复核通过，结果保存在 `verified_after_cleanup.json`。

复核全部证据使用以下命令。

```powershell
python hil/logs/f446_heap_index_20261112/verify_index.py --selected baseline
```

宿主模型可用新的输出目录重跑，例如以下命令。

```powershell
python hil/logs/f446_heap_index_20261112/directed/run.py `
    --source-root hil/logs/f446_heap_index_20261112/reference/bitmap `
    --out-dir hil/logs/f446_heap_index_20261112/directed/replay_bitmap
```

运行脚本拒绝覆盖已有镜像和采集批次。板上重跑先将 `reference/`、`fixtures/`
和六个 PowerShell 脚本复制到新的空批次目录。在工程根目录执行该批次的
`prepare_board.ps1`，再用 `build_diagnosis.ps1 -Engine bitmap -Phase libc -Opt O2`
构建。用 `run_suite.ps1 -Stage replay -Tags libc_bitmap_rtosfirstfinal_O2` 采集和
恢复。重新核对当前板卡、工具路径、探针编号及 COM 端口后，沿用脚本的备份和
恢复流程。现有结果为本机可复跑证据。
