## 临界区缺陷、修复与测试缺口

**B01：共享屏蔽槽位发布不原子。** 旧退出先把 nest=1 写为 0，再从全局槽恢复
BASEPRI。若此时优先级 0/4 IRQ 配对进入/退出底层临界区，就可用继承的 0x50
覆盖槽位；线程随后恢复错误值。进入侧也存在保存原值和发布 nest 之间的窗口。
600 次确定性交错有 36 次失败；百万次真实定时器干扰记录 2680 次线程屏蔽泄漏。
测试在采样后显式修复状态以继续输出，不代表内核能自愈。

最终在进/出共享元数据事务时保存 PRIMASK、短暂 cpsid i，更新槽位、计数及 BASEPRI
后恢复原 PRIMASK。临界区主体仍由 BASEPRI 保护，允许高优先级纯硬件 IRQ 抢占。
BASEPRI_MAX 保留更强屏蔽，原 PRIMASK 同样按保存值恢复；不是无条件开中断。
计数零退出/上限进入拒绝回绕，断言关闭时保留原状态，不承诺恢复错误业务。

**B02：解屏蔽后提前读出阻塞结果。** 无任何 giver 的空信号量，100 次有限等待
全部返回初始 OK，而 TCB 已记录 TIMEOUT。仅增加 PRIMASK 原子事务仍能复现；
`MSR PRIMASK` 后的读取可能先于已 pending 的 PendSV，错误寄存器值随任务保存。
在共同出口增加带 memory clobber 的 ISB，同步挂起异常的识别与后续结果读取。
这不是缓存刷新或 volatile 所能解决。[Arm AN321 §4.7](https://documentation-service.arm.com/static/5efefb97dbdee951c1cd5aaf)
说明相应中断同步要求。

旧测试只验证顺序嵌套与更强屏蔽恢复；业务 IRQ 为 6/7，不能抢占 BASEPRI 事务；
正常信号量交接又缺少“没有释放者绝不成功”的不变量。因此先前长时间 PASS 未覆盖
这两类缺陷。新阻塞夹具检查五种等待的返回值、TCB 结果、超时标志、时长和哨兵，
每镜像 516 PASS、500 次真实等待。

## 原报告的适用边界

高优先级 IRQ 抢占正常临界区时观察到非零 BASEPRI 合法，必须在线程配对退出后的
安全点判漏。0–4 IRQ 操作内核对象属于违约，默认 G-3 断言会拦截；关闭断言不使其
安全。测试 IRQ 只重入底层临界区原语，不把该行为解释为高 IRQ 可以使用 IPC。
NMI/HardFault 不受 PRIMASK 保护，禁止重入这些原语或对象 API。

BASEPRI=0x50 同时屏蔽最低优先级 PendSV，不能假定它会自然切入另一任务传播。
本工程 C 提交函数也没有报告所称的同组临界区调用；无需为此将 BASEPRI 加入 TCB。
临界区合法持有期间不会被 PendSV 切出。另补齐/前移 heap、perf、USB 共 27 处优先级
断言，属于契约诊断，不是对任意错误地址或非法上下文的普遍运行时拒绝。

BASEPRI，线程安全点仍全部零，验证两种观察不可混淆。

首轮压力同时检出信号量假成功及测试外设 TIM2 SR 恢复错误。后者定位为 SR 位，
不是 NVIC pending；修复夹具的 UG/UIF 有界握手、最终清 SR/读回/DSB/清 NVIC
顺序，保留原等值断言。无注入 bench 的临界区对 24→40 cycle、yield229→238、
往返1584→1666、sem唤醒445→496、queue唤醒532→575、ISR唤醒517→566。
临界区增加16cycle约95.2ns，属于当次平均测量，不能当作 WCET。

最终 main 原字节保留，日常固件恢复并重新下载，输出 task0/1 正常。
测试未覆盖物理 USB 主机链路、任意 IRQ 相位或全部配置/业务，无“所有 BUG 已排除”
