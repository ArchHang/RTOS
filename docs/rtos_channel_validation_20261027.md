# 静态借用通道：实现、性能与健壮性验证

本轮按“高吞吐数据传递与缓冲区安全”的优先级实现了可选的 `rtos_channel`。
它将静态缓冲池、发布 FIFO、代次票据、资源账本和关闭排空协议集成为九个 API，
生产者和消费者直接访问同一块 payload。默认关闭，现有队列及调度协议继续保留。
设计与完整示例见 [通道设计](rtos_channel_design.md)，源码入口为
[rtos_channel.h](../RTOS/Core/Inc/rtos_channel.h)、[rtos_channel.c](../RTOS/IPC/rtos_channel.c)。

零复制、固定池和指针队列都是成熟技术，不能把本模块称作行业首创或全面优于业界 RTOS。
本次的实际价值是减少驱动和业务自行编写的所有权、异常清理及关停协议，并把失败原因和
资源占用暴露为可检查的接口。它适合较大的采样帧、报文和 DMA 缓冲；小消息仍适合复制队列。

## 1. 已实现的行为

| 问题 | 实现方案及边界 |
| --- | --- |
| 大块消息复制占 CPU、延长中断屏蔽 | 原址写入、发布、接收和归还；通道不复制 payload |
| 重复归还、跨对象交接、旧描述符重放 | 地址、实例号、槽位、64 位代次及阶段共同校验；读写阶段使用不同票据 |
| 对象在同一地址重建后旧调用恢复 | 阻塞调用跨唤醒凭保存的整数地址和实例号重新查登记，再访问对象；旧实例返回 DELETED |
| 票据回绕造成身份复用 | 提前预留一对票据，耗尽返回 OVERFLOW；不回绕复用 |
| 丢失资源通知 | 资源变化广播唤醒，避免 READY 等待者随后被删/挂起吞掉唯一通知；代价为 O(W) |
| 多次唤醒延长有限等待 | 重试共用总预算，等待后到期即使资源已可用也不再授予 |
| 关闭时 DMA 仍访问内存 | close 阻止新流量，保留在途租约；确认硬件停止后归还，全部归还才可 deinit |
| 分不清积压和持有 | `free/writing/queued/reading` 四态守恒、峰值及饱和累计计数 |
| 断言关闭后非法 IRQ 侵入对象 | 新通道在运行时检查 syscall 优先级，不依赖断言开启 |

实现使用调用方静态存储，没有新增服务任务、堆分配、TCB 字段或调度热路径回调。
配置及错误码为追加扩展；旧错误码数值保留。编译清单由 16 个自研单元增加为 17 个，
工程总单元由 57 增加为 58。源码遵循全局 `c-code-style` 规范。

票据检查只保护 API 交接。应用仍须遵守租约、有效视图和元数据独占约定；旧裸指针、越界、
覆写未归还 descriptor、丢失唯一票据及删除持有缓冲的任务不能自动修复。
本实现不提供 MPU 隔离、CRC、自动 DMA/cache 管理或失去持有者后的强制回收。

## 2. 真实测试环境与证据

NUCLEO-F446RE，STM32F446 / Cortex-M4F，168 MHz，1 kHz tick，GCC 11.3.rel1。
ST-LINK `066DFF555775514867092907`，SWD 下载并验证，USART2 / COM3 / 115200 / 8N1。
每个正式镜像保存构建命令、输入散列、ELF 身份、实际探针及下载日志、串口原文和判定结果。
源码快照在每次构建前后保持一致；不同镜像之间未使用夹具的变化按各自 manifest 保留。
SHA 用于关联镜像和证据，不证明程序正确性。

宿主测试使用真实生产 C 和脚本调度替身，不等同于 Cortex-M 抢占验证，也未使用 ASan/UBSan。
它覆盖容量 1/3/16 的随机交错，并额外验证合法上限 256 块完整生命周期、8 个登记通道末项热路径、
内存 canary、同地址重建、保护页禁止访问旧控制块、票据/实例耗尽以及 descriptor 覆写的契约边界。
没有将数千万次模型断言解释为数千万个独立业务场景。

原内核回归包括 audit 117、selftest 432（另 10 INFO）、boundary 103、FPU/低层 24＋22、
互斥继承 910、混合等待 1,600（73 阶段）、生命周期 80、递归/锁边界 87、登记容量 259、
16 业务任务压力 30 秒的 165 项验收，以及两种 mask 各 600 个临界区组合与附加检查。
新增生产文件和夹具严格编译无警告；完整测试镜像仍有原 `main.c` 条件排除演示代码的
25 条 unused 告警，日常构建为 2 条，均逐行核对，没有冒称全工程零警告。

新功能 33 个镜像组成如下：

| 夹具 | 配置与数量 | 每镜像判据 |
| --- | --- | --- |
| `channel_checks` | BASEPRI/PRIMASK × assert 开/关 × O0/O2/O3，12 个 | 413 项；含真实 IRQ 0/4/5、删除/挂起、重建与四组迟到资源截止测试 |
| `channel_stress` | 同上，12 个 | 48 项；4 生产者、4 消费者、TIM7 p5，4,608 条精确交付、校验、去重及所有块归还 |
| `channel_dma` | 两种 mask × assert 开/关、O2，4 个 | 36 项；真实 DMA2 Stream0、16 KiB 正常发布及在途关闭 |
| `channel_profile` | 两种 mask、assert 开、O2，2 个 | 1,040 项及 280 条真实 IRQ 延迟观测 |
| `channel_bench` | BASEPRI、assert 开、O2/O3，2 个 | 1,366 项及 270 个测量格，三条数据路径完整对照 |
| 损坏对照 | BASEPRI、assert 开、O2，1 个 | 一处 payload 损坏；仅允许指定 3 项 FAIL，8 块全部归还 |

正常压力矩阵合计完整交付 55,296 条消息，各镜像四个消费者均实际参与，任务及 IRQ 诊断没有
异常返回或接收超时。负向镜像接纳/收取/归还仍为 4,608 条，只有 4,607 条内容有效，
`checksum_errors=1`，说明测试可以发现指定的数据破坏，而不是只检查系统仍在运行。

## 3. 压力夹具异常的追查与修正

早期 O0 压力夹具曾报告 `errors=1`，同时消息、唯一性和资源账本全部正确。
新增诊断版一度无法重现该计数，且发现最低优先级消费者可能没有处理任何消息。
没有将这两种现象直接归因于内核，也没有删除失败证据。

随后重新加载归档的原失败 ELF，在 SRAM `errors` 设置硬件写监视点。
第二次运行停在 `add_error` 的临界区出口；DWARF 调用栈显示：

```text
consumer_task(argument=0x2)
    status = RTOS_ERR_TIMEOUT
    consumer = 2
    delivered = 16
channel.stats.receive_timeouts = 1
channel.stats.free = 8
```

继续运行至结束，4,608 条消息仍全部消费、全部归还。
这确认该次错误来自消费者的有限接收超时；不能再把它描述为“未定位”或数据丢失。
固定优先级调度并不保证跨优先级公平分配，而夹具此前每 16 条只让出 1 tick，
将“每个消费者一定及时取得消息”作为无条件断言并不成立。

最终夹具为每次成功归还后的消费者设置 1 tick 业务处理节拍，保留 1,000 tick 有限接收等待，
并保留 8 个任务与 IRQ 的首错状态、阶段及等待诊断；没有用无限等待遮蔽超时。
这一负载配置在 12 个正式镜像中均通过。它提供业务运行窗口，不是内核新增公平性保证。

原镜像、失败日志、诊断快照、硬件回溯及 Flash 字节读回核验保存在
[原失败证据](../hil/channel_20261027/evidence/preflight/original_stress_failure/)。
GDB 的 `compare-sections` 报过 CRC 不匹配，随后直接读取 Flash 并逐字节核对全部加载 section
及 `.data` 的 Flash 初值，结果一致；未加载的 ELF segment 对齐填充不作为代码差异。
调试期间的 halt 会影响时序，因此回溯用于确认返回状态，不用于计算生产时延。

开发期间还修正了宿主 64 位尺寸比较告警，统一使用乘法前的除法上界检查。
测试设施补充了 Windows 原生目标清理，防止 `make clean` 缺少兼容 `rm` 时复用旧对象；
验收器按真实输出修正了路径、成功标记及阶段汇总解析。相关预检失败按原样归档，正式矩阵均重新完整编译。

## 4. 吞吐：收益与代价

三条路径为：按值复制 queue、mempool 加指针 queue、完整 loan channel。
每格同样执行 `128 × capacity` 条消息，重复 3 次并轮换路径顺序；容量 1/3/16，
消息 16/64/256/1,024 字节，另外测 4,096×1/3 和 16,384×1，共 15 个形状。
`ipc` 排除三条路径共同的填充/校验；`e2e` 包含相同的完整 payload 填充和验证。
计时使用真实 DWT，允许正常中断；数据有效性及计数周期范围均单独检查。

下表取 O2、容量 1 的三次 `cycles/messages` 中位数，单位为周期/条，已四舍五入：

| 字节 | 复制队列 e2e | 池＋指针队列 e2e | 通道 e2e | 通道相对复制 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 1,295 | 1,613 | 4,663 | 慢 260.0% |
| 64 | 3,267 | 3,104 | 6,155 | 慢 88.4% |
| 256 | 11,151 | 9,064 | 12,119 | 慢 8.7% |
| 1,024 | 42,696 | 32,914 | 35,968 | 耗时减少 15.8% |
| 4,096 | 168,906 | 128,303 | 131,373 | 耗时减少 22.2% |
| 16,384 | 673,204 | 509,716 | 512,858 | 耗时减少 23.8% |

16 KiB 的纯 IPC 交接从复制路径约 164,569 周期降至约 3,986 周期，约 41.3 倍；
加入业务填充/校验后，收益降为上表的 23.8% 耗时减少。不能把纯 IPC 比例推广到完整应用。
同形状下原始池＋指针队列的纯 IPC 约 864 周期，通道耗时约为该路径的 4.6 倍；
16 KiB e2e 下通道比该路径慢约 0.6%。这是附加检查、票据和账本的成本，不能忽略。

因此推荐按消息规模、关停需求和误用风险选择接口，不建议把全部小队列替换成通道。
完整 O2/O3、三种容量的数字见 [throughput.csv](../hil/channel_20261027/evidence/analysis/throughput.csv)
与 [performance.json](../hil/channel_20261027/evidence/analysis/performance.json)。
上述测试没有包含多通道同时活跃、任意等待者规模或所有业务负载的吞吐上界。

## 5. 中断响应与资源成本

独立 profile 镜像在最外层临界区入口的软件 hook 中置 TIM7 p5 pending，真实 IRQ 只记录 DWT
时间与次数；不启用 TIM7 timer，不在 IRQ 打印或调用 RTOS。每个点观察 8 次，包含仪器成本，
不是外设边沿到 ISR 的测量，也不是最坏执行时间证明。

BASEPRI、O2、168 MHz 的观测如下：

| 操作 | 字节/等待者 | 观测周期范围 | 换算时间 |
| --- | --- | ---: | ---: |
| 空临界区仪器基线 | — | 79–79 | 0.47 µs |
| queue send | 16 KiB / 0 | 82,172–82,172 | 489.12 µs |
| queue receive | 16 KiB / 0 | 82,149–82,149 | 488.98 µs |
| loan acquire | 16 KiB / 0 | 756–756 | 4.50 µs |
| loan publish | 16 KiB / 0 | 774–774 | 4.61 µs |
| loan receive | 16 KiB / 0 | 884–884 | 5.26 µs |
| loan release | 16 KiB / 0 | 891–891 | 5.30 µs |
| loan publish | 256 B / 4 | 1,114–1,114 | 6.63 µs |
| loan release | 256 B / 4 | 1,231–1,231 | 7.33 µs |

当前观察证明大 payload 不再延长通道的复制屏蔽窗口，同时显示广播等待者确有额外成本。
登记校验随配置 C、广播随等待者 W、初始化随块数 N 增长；不承诺任意规模下固定周期。
PRIMASK 及全部尺寸数据见 [irq_observations.csv](../hil/channel_20261027/evidence/analysis/irq_observations.csv)。

默认 8 项登记下模块 BSS 为 104 字节，另需应用提供 payload、每块 32 字节 slot、控制块和视图。
严格编译矩阵采用 function/data sections，O2 的单模块 text 为 5,608 字节；
此前无这两个选项的独立编译为 5,596 字节，二者不是同一构建。
独立对象尺寸不是最终链接 Flash 增量，实际集成需查 map。

默认关闭的日常镜像及恢复日常模板后的镜像，入口、可装载段映射、全部 SHF_ALLOC 区域的
地址、尺寸与内容均与扩展前已验证日常镜像一致，见
[默认关闭比较](../hil/channel_20261027/evidence/baseline/default_off_equivalence.json)和
[最终恢复比较](../hil/channel_20261027/evidence/baseline/restored_daily_equivalence.json)。
这是当前日常应用没有增加运行代码和静态状态的证据；不推广为所有编译器和用户配置的保证。

## 6. 可交付范围与后续方向

本轮交付为可选数据通道、应用设计示例、宿主模型、实板夹具、可复跑脚本及原始证据。
正式板测共 48 个镜像，最终关联复核见
[final_summary.json](../hil/channel_20261027/evidence/final_summary.json)。
`main.c` 保持原内容，日常构建模板和板上日常固件已恢复，并确认 `task 0/1 running`。
保留正式源码、日志、必要的失败定位与本地镜像，清理临时对象、复制夹具、Python 缓存及重复构建日志；
历史批次不改写。本轮功能代码尚未提交或推送 Git。
不是对未知缺陷不存在的证明。M7 项只做代码生成，仍使用 F446 设备头；没有 H7 BSP、D-cache、
MPU 或 M7 DMA 的实板结论。F446 DMA 为真实内存到内存传输，未据此声称 USB、ADC 外设采样均已验证。

更进一步的业务进度契约、等待依赖解释、消息时效策略和 MPU 租约隔离仍是未实现路线，
见[设计文档](rtos_channel_design.md#12-后续路线尚未实现)。应分别建立可测收益与故障边界，
不以未经验证的强制回收、关闭校验或改变基础调度语义换取性能数字。
