# RTOS 修复、优化与验证交付汇总

日期：2026-10-13。验证平台：NUCLEO-F446RE，STM32F446 Cortex-M4F，168 MHz，1 kHz tick。

本次提交整合已有工作区改动、后续源码审计修复、两阶段性能优化和综合业务压力测试。任务开始前已有用户修改，包括堆统计接口、自测及文档整理，因此以下分类描述最终交付内容，不把全部 Git 差异都归为本轮新发现的缺陷。

## 改动内容

| 范围 | 最终行为与修改目的 | 详细记录 |
|---|---|---|
| 调度与任务生命周期 | 正确处理启动前及嵌套调度挂起、取消过时候选、创建句柄先发布、静态 TCB 构造中间态及无效任务句柄 | [审计报告](rtos_audit_20261012.md) |
| IPC 与等待链 | 维护阻塞／超时／删除路径的等待归属和优先级信息，加固 queue、sem、mutex、event 的参数及状态契约 | [审计报告](rtos_audit_20261012.md) |
| 内存与软件定时器 | 检查非法内存归还和对象状态，处理定时器回调修改活跃结构及旧代次命令 | [审计报告](rtos_audit_20261012.md) |
| USB 与 CherryUSB | 加固传输预算、RESET 会话、控制请求／MSC 输入、端点与 FIFO 配置及 OSAL 生命周期 | [审计报告](rtos_audit_20261012.md) |
| 性能 | 保留临界区局部计数、mutex 有序队首计算、PendSV 接收返回 TCB、链接快照及信号量 ISR／任务指针复用 | [第一阶段](rtos_optimization_20261012.md)、[底层阶段](rtos_lowlevel_optimization_20261012.md) |

公共调度接口的 void 包装继续保留，PendSV 使用新增内部返回指针的入口。不要把局部优化理解为所有 API 均为 O(1)：等待链尾插和某些等待者选择仍可能线性扫描；本次没有增加传递优先级继承。

压力模型包含 16 个业务任务，优先级 5–20；四个采集任务和 TIM6／TIM7 ISR 向同一 queue 投递，四个消费者接收，另有共享 sem、mutex、ANY／ALL／timeout event 和控制／维护角色。观测到四个 queue 接收等待者、两个共享 sem 等待者、三个 event 等待者、真实优先级继承及中断嵌套。队列满、发送超时和 sem overflow 被单独计入背压，不计入成功消息或成功 give。

负向对照及各阶段诊断／无效采集不计为正常 PASS。初次板卡未接入时只完成构建，未下载或执行，也不计为板载测试。本轮业务压力未发现新的内核故障；测试器的栈水印、有限等待状态、关停握手、日志优先级及 Windows PowerShell 数组兼容问题已经修正。

## 性能结果的适用范围

以下对比以第二阶段开始时已修复、已完成第一阶段优化的版本为基线，不是与整个提交前的 Git HEAD 比较。

| 指标 | 第二阶段基线 | 保留组合 | 变化 |
|---|---:|---:|---:|
| perf BM2 | 1607 cycle | 1296 cycle | −19.35% |
| 普通 bench BM2 | 1394 cycle | 1307 cycle | −6.24% |
| yield（两种夹具） | 234／235 cycle | 229 cycle | 降低 5／6 cycle |
| 普通 bench BM5 创建／删除 | 6121 cycle | 6137 cycle | +0.26% |
| 普通 bench BM4 最大值 | 774 cycle | 795 cycle | 增加 21 cycle |

第一阶段保留方案的临界区进出由 30 降至 24 cycle，mutex 的 4／8 等待者计算由 71／107 降至 46 cycle。源码指令减少不能保证所有负载吞吐提高；收益、退步、候选撤回及布局差异均保留在详细报告中。

## 发布证据与复现条件

仓库保留权威测试源码、构建／采集脚本、原始串口和下载日志、文本反汇编、编译记录及源码／固件身份 JSON。历史路径、时间及 ST-LINK 序号属于原始测试元数据，未改写为另一台机器的运行结果。

ELF、目标文件、Debug 构建目录和回滚源码快照仍在测试机本地归档，不随源码 Git 提交。JSON 中的 ELF 哈希可用于追溯，但克隆仓库只获得文本证据；缺少原 ELF 时，不能直接运行依赖这些文件的完整原始身份复核。重新构建的 ELF 也不能冒充历史镜像，因为工具路径、调试信息及构建布局可能改变其哈希。

当前 HIL 工具使用测试机的 Windows 工程路径、CubeIDE／CubeProgrammer 路径、COM3 和指定板卡。其他电脑需按 [HIL README](../hil/README.md)配置环境后建立新批次，并使用新的 tag、日志目录及源码基线；冻结的历史夹具和脚本保持字节不变，以保留已有源码身份。历史 FreeRTOS 对照工程及部分早期资料位于本地外部目录，不属于本次可独立运行的仓库资产。

有限压力测试覆盖的是合成工业输入、混合 IPC、真实定时器中断、背压恢复和资源清理。物理 USB 枚举／传输、真实传感器及 DMA 链路、掉电恢复、所有任务生命周期交错、全部事件消费语义、任意堆碎片模式和硬实时 WCET 未由本次测试证明。
