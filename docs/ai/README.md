# AI 辅助开发使用指南

本资料描述当前 RTOS 的实际公共接口及调用约束，供工程师和 AI 检索、编码、审查及
定位问题。它不增加 MCU 功能，也不改变内核行为。核对基线为
`87bfbe4a6efc50f9b828128c713a1b5af2900ef8`；目标为 F446、Cortex-M4F、单核、GCC hard-float。

## 2. 完整性范围和事实层级

主清单覆盖 `RTOS/Core/Inc/` 的全部自研公共头：函数声明、头内联函数、函数式宏、
相应的条件关闭形式及公开类型/配置的使用约束。声明在公共目录中的调度器内部原语、
服务任务、异常入口和弱钩子也逐项分类，不能因为它有头文件声明就把它当作应用入口。
CherryUSB 的 OSAL 桥接及驱动回调在服务契约附录单列，不与自研应用 API 混为一类。
第三方 HAL/CMSIS/CherryUSB 的全部接口不在本套自研 API 完整性统计中。

每份契约说明参数、单位、上下文、可能阻塞、返回及失败影响、存储寿命、配置与来源。
函数原型及名称须与头文件一致；语义逐项对照实际分支和下层调用。
契约中的“必须”是调用者义务，“实现检查”是当前代码确实执行的验证；后者不一定
覆盖前者。未初始化、越界、已释放、并发改写或伪造指针不因 API 有参数检查而变为安全。

阅读优先次序是：用户的当前要求 → 对应版本的接口契约及已知偏差 → 声明/实现与测试
相互核对 → 架构和历史参考。实现也可能有缺陷；发现偏离预期时保留复现证据，不能把
“源码这样做”自动解释成期望行为。本阶段只记录已核实偏差，不修改生产实现。

## 3. 通用单位和上下文

| 项目 | 当前规则 |
|---|---|
| 任务优先级 | `0`最高，默认32级；基础优先级与互斥继承后的有效优先级不同 |
| 栈容量 | 任务/USB线程相关参数以各函数契约为准；普通任务栈参数单位是32位字，不是字节；应用提供8字节对齐 |
| 普通延时和IPC等待 | 单位tick；默认1000 Hz时1 tick=1 ms，不能把此等式用于其他时钟配置 |
| 不等待/永久等待 | `RTOS_NO_WAIT=0`；`RTOS_WAIT_FOREVER=0xffffffff` |
| 有限等待 | 使用`1..0x7fffffff`；当前普通调度等待路径把更大值按永久处理，不返回超范围参数错误；不是系统运行期限 |
| USB超时 | 多数OSAL/CDC/HID接口使用毫秒，必须查对应契约；`rtos_usb_timeout_ticks`向上取整且有限结果饱和到`0x7fffffff` |
| 数据容量 | queue元素、heap请求、mempool块长通常是字节；不能把块数、元素数、有效长度混用 |
| 时间回绕 | 32位tick会回绕；用相应有界差值算法，不以普通`now >= deadline`代替；统计字段另有自己的回绕边界 |

本套文档使用以下上下文术语：

- **启动上下文**：Thread模式、调度器尚未启动。仅使用契约明确允许的初始化或不阻塞路径。
- **任务上下文**：Thread模式、存在合法当前任务；可能阻塞的操作还要求调度器运行、未挂起、无外层临界区。
- **系统调用级ISR**：允许进入内核的可配置IRQ；本F446默认逻辑优先级5..15。
  传给`NVIC_SetPriority`的是逻辑值，`BASEPRI`门槛为编码值`0x50`，不能交叉使用。
- **高优先级ISR**：本F446默认逻辑0..4。涉及内核共享状态的API禁止使用；纯读取寄存器或
  明确允许的单值快照按其局部契约处理。PRIMASK模式不自动放宽应用的中断契约。
- **NMI/故障上下文**：不使用普通分配、IPC、调度或临界区操作；采集有限有效现场并进入故障处理流程。
- **内部/移植入口**：由规定的调用链和保护条件使用，不是应用自由调用的替代API。

`RTOS_ASSERT_ISR_OK`的优先级检查仅在断言开启时存在。关闭断言不保证返回`RTOS_ERR_ISR`，
也不使非法IRQ访问共享状态安全；真正的运行时ISR分支由每个API单独说明。
软件定时器回调运行在服务任务，阻塞会拖延整个定时器服务；它不是硬件IRQ。

## 4. 对象、数据和并发义务

调用者提供的控制块、存储、栈、任务参数、回调参数及保留的名字，都必须满足对应
函数的有效期。`init`不是通用代次句柄系统，按值拷贝控制块不会创建独立对象。
对象同址重建、动态任务删除后的旧地址、池块复用后的旧指针不能获得通用撤销保护。

queue按元素大小复制字节。传入结构体会复制结构体；元素为指针时只复制指针值。
阻塞发送/接收会保留用户缓冲地址直到调用完成，因此不能提前释放或并发修改。
“直传”路径跳过环形缓存但仍有一次`memcpy`；不能据名称宣传为无数据复制。

失败是否保持输出要逐函数查：例如通知等待、事件位返回和部分观测接口不能套用
“所有错误输出不变”。返回OK的层次也不同：queue是消息已接纳，异步timer命令是命令
已接纳，USB写完成还须检查实际长度；这些均不等于下游业务完成或存储可以释放。

`volatile`不替代互斥、原子协议或对象寿命同步。单值查询不保证与下一次查询构成一致
快照；临界区也不能让高优先级ISR访问内核共享对象变得合法。

## 5. 配置、构建和资料同步

多数配置宏在`rtos_config.h`直接定义，不能假定命令行`-D`能覆盖。当前BASEPRI和ASSERT
有`#ifndef`，其他配置的验证使用校验工具生成的独立头文件副本，并记录精确变更。
生产头文件及日常构建保持不变。模块“关闭”是否有完整存根，也必须查实际源分支。

16个自研C单元分布在Core/Src、IPC、Memory、Services、USB、Port。完整日常工程57个
对象，不能只编Core/Src。F446是已集成目标，端口目录名不证明其他M7芯片已上板。
本资料的示例通过独立编译工具验证；编译、部分链接与真实运行的含义在结果中分开。

修改头文件或行为后，重新生成索引、复核契约、编译示例、检查链接和原型覆盖；
若只改文字则不需要重复无关硬件测试。原始结果不重写为新版本的成功证据。
已知差异在[调试指南](debugging.md)及各API记录中列明；后续修复应另有明确任务范围。
