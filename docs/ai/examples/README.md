# 可编译调用示例

这些文件是独立文档示例，不加入`main.c`、CubeIDE对象清单或日常固件。接口统一声明在
[ai_examples.h](ai_examples.h)；`ai_example_*`仅是示例函数名，不是RTOS新增API。
它们展示调用及错误处理，不构成运行测试或所有API的演示覆盖。handbook.c提供完整的替代
应用组织示例，仍依赖目标BSP与工程集成，不能仅凭部分链接作为可运行固件。
全部公共API的语义覆盖以[契约索引](../api_index.json)为准。

| 文件 | 用途及调用前提 |
|---|---|
| [handbook.c](handbook.c) | 一次启动的queue/mutex/event业务链、周期任务及替代启动；下文说明其失败/寿命协议 |
| [task_notify.c](task_notify.c) | `rtos_init`后创建持久静态worker；创建返回OK后才能公布其地址、使能会通知它的IRQ；VALUE通知代表最新值，重复到达可合并/覆盖，不保证逐条消费 |
| [ipc.c](ipc.c) | queue/sem/mutex/event各自初始化一次后再发布；普通等待及mutex更新在运行任务中调用；`*_from_irq`必须在合法系统调用IRQ，或由合法任务调用 |
| [memory.c](memory.c) | 堆示例在本次调用内申请/使用/归还；固定池对象和底层数组持久，避免perf注册表保留失效栈地址；池只初始化一次 |
| [timer.c](timer.c) | 定时器子系统已初始化，配置开启时`rtos_init`会自动完成；关闭该自动初始化时须先显式调用`rtos_timer_init`；对象/回调参数终身有效，delete后不立即释放或重建 |
| [observation.c](observation.c) | 正常任务读取perf输出，检查每次状态；两份快照不是联合事务；临界区示例不阻塞、不打印，保持成对退出 |
| [usb.c](usb.c) | 板级时钟/引脚/IRQ/设备栈初始化及真实主机连接由业务完成；函数返回实际字节数，调用者核对是否完整；关闭配置的示例返回0，不表示USB成功 |

## 集成顺序和互斥使用

1. 板级准备，检查`rtos_init()`结果。
2. 只初始化所选示例的私有对象，逐个检查prepare返回值；多个prepare不是事务，失败时
   不得启动引用失败对象的执行者。局部初始化演示各自独立，应用负责自己的回滚策略。
3. 创建worker成功后公布TCB；IRQ优先级满足门槛后才使能对应中断。
4. 调用`rtos_start()`。在运行任务里使用等待、互斥锁、perf和USB业务入口。

`ai_example_queue_roundtrip`要求私有队列初始为空且整个调用由唯一执行者使用，用来说明
按值复制和输出检查；它不能与`ai_example_queue_send_from_irq`或其他消费者并发使用。
IRQ发送例子供另一种集成方式选择，接收逻辑应在本示例文件内使用私有队列，或由应用
按此模式建立自己可访问的队列；当前示例没有导出该静态队列句柄。不要把这些入口
全部同时调用后假定它们构成已验证的生产数据管线。

事件等待返回位快照而非错误码。仅当`(result & 3U) == 3U`时条件满足，其他结果不能
直接等同于超时或某一种错误。二值信号量已满时give返回OVERFLOW，业务须按事件合并
或计数需求处理，不能把所有非OK都无条件重试。

没有示例替代对象关闭协议、硬件初始化、USB物理互操作或存储寿命同步。
任务函数不会返回；控制块/栈和池均有静态寿命；临界区示例要求target/previous自然对齐、
可访问且不重叠。示例不实现自动任务删除清理或撤销裸指针。

## 编译验证的含义

使用[独立编译工具](../../../hil/ai_docs/README.md)对这些真实`.c`文件编译，记录命令、
编译器版本、输入身份和结果。设计手册的内嵌函数/完整文件以这些源文件为准，使用
[摘录检查器](../../../hil/ai_docs/check_handbook_examples.py)逐字核对，避免正文与源分叉。
条件关闭配置在隔离头副本中验证，不修改生产配置。

编译能检查声明、类型、宏分支和目标代码生成；部分链接还能发现本次对象集合中的
重复定义及未满足的自研符号。它们均不证明时序、IRQ优先级、业务进展或USB收发已上板。

## handbook业务例程的使用协议

本目录当前7个C文件共31个公开演示函数。handbook.c的8个演示入口不属于RTOS新增API：

1. 调用者先完成BSP时钟、向量、FPU及内存准备。ai_example_handbook_start内部依次rtos_init、
   pipeline_init、建立周期生产者、rtos_start；成功后不返回，不与日常main同时启动。
2. 所有控制块、消息存储、TCB与8字节对齐栈永久存活。初始化仅一次，在调度/IRQ发布前完成；
   ready此后不变。初始化失败不回滚已经建立的静态对象，禁止继续start、放行来源或直接重试，
   由应用执行启动错误处理/复位。这是明确的fail-stop策略，不是可热重启组件。
3. 周期生产者优先级12、消费者10，各256字栈；默认timer/idle另计。生产每20tick调用一次，
   有限发送使用10tick等待预算，失败跳过并置错误hint；ISR发送NO_WAIT，其调用者必须处理拒收。
4. 每消息复制sequence/sample两字段；阻塞发送的局部消息保持到函数返回。sequence模2^32递增，
   与是否接纳独立；接多个源时须自行规定来源/序号命名空间，不将其当作全消息账本。
5. consumer在mutex下更新最后结果，processed_count饱和；read_result用锁取得一致快照，
   无首次结果或失败时不写输出。结果仅是最后值，不保证每一条处理结果独立交付。
6. RESULT_READY是合并提示，wait_hint清这个位而不清FAILED。返回完整快照可能仅有FAILED=2，
   必须按RESULT_READY掩码判断；结果mutex负责数据一致性，event不替代它。
7. control_worker只适用于单一生命周期控制者持有的、已到安全点且无持锁/未完成等待的worker，
   正常任务上下文使用。它不保留原先已挂起状态，也不回滚资源/外设事务，不作为通用暂停协议。

本例不演示动态关闭、事务补偿、自动重传、物理外设配置或强制删除后的业务恢复。
这些边界在[设计手册16.5/16.11](../../rtos_design.md#165-综合业务模型与有界关停)展开。
