# RTOS 测试覆盖与历史教训

本文维护测试入口、验收判据和已确认的覆盖局限。当前接口语义以
[API 契约](ai/README.md)和[设计手册](rtos_design.md)为准。当前交付包括 F446 上的 USB
定向缺陷复现、两板的内核结构优化 A/B，以及两板的实板功能回归和压力测试。按场景查询
[交付验收矩阵](#release-validation)、[执行入口](../hil/README.md)和[可复核证据](../hil/evidence/2026-11-11/README.md)。

旧报告中的“当前431 PASS”“USB完全未测”“非传递继承”等描述属于各自历史阶段，
已不适合作为现有实现结论。已退役的旧批次以历史归并记录为准。曾入库的原文可在 Git
历史查找，未入库资产的保留范围见相应每日日志。本次交付另有原始输出和身份清单。
新验证必须按实际构建输入和烧录镜像建立身份。

## 2. 判据与失败分类

1. 每次运行绑定源码、配置、工具链、构建和实际下载镜像，保留完整命令及原始输出。
   接收对应结束标记；主机超时、输入身份变化、FAIL、覆盖次数不足均不能正常通过。
2. 基础自测的真实USART2 ISR握手由主机在`ST|ISR|ARM`后回发`X`，缺少握手不能把
   ISR子集当作已执行。缺结束行时不能只统计已经打印的PASS。
3. 检查失败返回后的对象计数、队列内容/顺序、所有权、等待归属及目标哨兵，避免只
   检查错误码；释放者不存在时绝不能成功，迟到消息不能写入已超时接收缓冲。
4. 并发覆盖需确认真实BLOCKED/DELAYED、等待对象与优先级，而非仅创建了若干任务。
   业务检查每个角色的进度、接纳/拒收、来源序号/内容、令牌和资源守恒。
5. 停止生产→排空成功接纳消息→停止消费者→确认无在途访问→销毁对象，收尾有界。
   主机无法取得结束证据时报告失败或未验证，不能补写PASS。
6. 负向对照必须由正常判据发现指定破坏，单列预期失败；不能预置错误数或把任何
   断言都算成功。环境未连接、验收器错误、源码身份失效也分别记录。

## 4. 重要的跨模块故障教训

- event等待节点曾残留旧sem位图指针，随后调优先级会污染无关对象。超时/删除/挂起
  还曾不清位，共享优先级位曾在仍有同级等待者时被误清。测试要覆盖跨对象复用和
  “位图恰等于真实等待优先级集合”，不能只检查链非空。
- notify超时残留blocked_on曾截断后续delay；同一任务连续调用不同阻塞接口需要
  校验清理。有限延时上界曾把恰好0x7FFFFFFF误判为永久，已修复边界比较；这不代表
  当前支持任意32位有限等待，详见契约。
- timer改周期曾漏上界而回调风暴；活跃对象重复create曾造成自环；回调操作活跃链、
  服务任务重新计算等待时机、同址旧命令也需要覆盖。异步delete成功不是存储可释放屏障。
- 过小任务栈曾破坏heap头，继而创建返回NO_MEM，测试再用未初始化句柄delete才崩溃。
  API最小栈96words只是拒绝边界，不能当作任意阻塞/FPU调用的安全栈预算。
- 串口完全静默曾是监听晚于启动输出，不能直接推断没有执行；先建立镜像、复位和
  采集顺序，再结合调试器及故障寄存器定位。

## 5. 构建与清理纪律

宏变化未必触发make重新编译；复制旧时间戳也可能复用旧对象。Windows的make clean
曾因缺rm留下对象，不能只看返回码。检查实际编译命令/对象清单、有效预处理配置和
最终链接输入，使用当前构建脚本的隔离/恢复流程；不要按旧报告行号或旧源码目录改文件。

源码整理曾误删内部原型和main声明，被编译警告及异常text尺寸发现。按明确内容定位，
检查差异及完整生产文件身份；资料更新不要顺带改内核。文档检查和清理不是功能回归。
最新可保留的验证证据及生成目录规则见[HIL入口](../hil/README.md)。

## 6. 分批结果与覆盖边界

以下结果按验证阶段记录。产品级 WCET、物理 USB 主机互操作、H743 外部 SDRAM、摄像头和显示、
任意中断相位与锁拓扑、完整 Tick 周期的自然回绕、存储重用与掉电恢复仍需单独验证。H743
已测 AXI/DTCM、缓存开关、定向失效及 DMA2 内存搬运，实际缓存命中率和分支误预测率未直接测量。
关闭断言后仍须遵守 API 上下文和指针寿命契约。

### 6.1 2026-11-11 的实际验收范围

O0 默认直连路由的 MSP 保持稳定。切换到旧 C 包装后，首任务 MSP 低了 4 字节，
单次 PendSV 再低 4 字节，并在后续任务切换触发异常。修复版同用例 4 项通过，
包括 32 轮阻塞恢复。定向回归的旧版为 28 通过、19 失败，修复版在
BASEPRI/O2 与 PRIMASK/O3（无断言）均为 47 通过、0 失败。

120 秒生产型压力以 16 个 worker、6 个消息来源、三层真实 IRQ 检查负载与关停。
165 项通过，成功接纳的 263,307 条消息逐条核对，屏蔽泄漏及合成控制截止期违约均为 0。
此阶段的用例运行于 F446。随后补做的长时运行与 H743 实板分别见第 6.8、6.10 节。
已确认修复与仍待复现的源代码风险见[当日记录](logs/2026-11-11.md)。

### 6.2 多优化级与多芯片配置

后续实测补齐 F446 的 O0/O2/O3 唤醒基准、非法 SysTick 配置拒绝及重试、
Thread/PSP、FPU、ISR/MSP 和 PRIMASK 故障现场。最终固件运行 O0/队列 8
与 O3/队列 4 两个 30 秒负载，每个 165 项通过。H743 在此阶段完成实际 CMSIS 头下的
交叉编译和部分链接。根因、性能回退和测试命令见[当日记录](logs/2026-11-11.md#multi-target-optimization)。

### 6.3 真实串口推理项目

STM32F446 的 USART2 接收实际二进制帧，并由单一模型任务运行仓库的 1D-CNN。
实板和本机同源参考核对 320 次推理结果。坏 CRC、非法长度和 12 次突发过载分别
验证拒绝、重新同步及槽位背压。队列优化以单源文件 A/B 建立因果范围，并通过
阻塞、销毁窗口、三种优化级和 20 秒混合 IPC 压力验证。完整记录和测试边界见
[实板项目记录](logs/2026-11-11.md#uart-project)。

### 6.4 独立采集、租约监督与总线恢复项目

在相同 F446 板和 O2 夹具下，旧版复现了固定池描述符被覆盖、定时器服务恢复后
额外等待 40 tick、互斥锁销毁后返回虚假的取锁成功。修复版的 3 个项目在 O0、O2、
O3/PRIMASK（关闭断言）每组共 28/28；O2 的混合并发压力跑了 30 秒，165/165，
65,956 条已接纳消息全部对账。ADC 和 DMA 走真实硬件，总线寄存器为模拟；
H743 本批只交叉编译和部分链接。[实测记录和未覆盖边界](logs/2026-11-11.md#project-robustness)。

### 6.8 长时并发与回绕

### 6.10 STM32H743 实板兼容性

H743 Rev V 的 480 MHz 板测覆盖 O0 包装向量、O2 直接向量与 O3/PRIMASK 关闭断言，

阻塞拒绝、MSP、浮点现场与 SysTick；另有 16 轮加速 IPC 回绕。两轮 120/30 秒综合压力
各通过 165 项，共核对 328,989 条消息。DMA2 真实 IRQ 验证了 AXI 缓冲在 D Cache
开关两组各 32 次传输，包含维护后的字节和相邻行检查。原固件完整读回一致。

## 10. 历史审计的稳定引用

保留本节编号，供生产私有头中的SD-1说明和旧资料检索，不代表目录中还有完整旧批次。

### 10.1 已修复：挂起调度器期间调用阻塞API

旧实现`rtos_sched_suspend()`后停止普通tick处理，但阻塞入口仍可摘除当前任务；
随后没有超时推进，`rtos_task_delay(60)`实板曾无法返回。修复统一阻塞许可守卫：
需要等待时，状态型接口拒绝为ERR_SCHED，delay类void立即返回，event_wait返回0；
可立即完成的非阻塞路径照常。守卫在等待入链和继承修改之前执行，避免留下半状态。
挂起调度不等于暂停SysTick硬件，也不能作为任意持锁阻塞流程的替代。

历史FIX19为12条检查，包括挂起态、拒绝等待、非阻塞可用、tick冻结、恢复后超时；
其原批次为selftest431/0/11INFO、boundary103/0。当前精确入口及例外以
[内核契约](ai/contracts_kernel.md)和[IPC契约](ai/contracts_ipc_memory.md)为准。

### 10.3 已作废：旧WCET测量方案

旧D9试图以定时器相邻ISR差值推导最长关中断窗口，但5ms控制屏蔽没有在读数中体现，
方案作废，190ns等数字不能引用为上界。旧记录同时声称TIM6优先级4、BASEPRI0x50及
“该中断应被屏蔽”，这些前提本身不一致，不能照抄为成立事实。16位时基混叠仅是当时
未确认的原因假设，不能作为已证根因。空临界区对的平均周期也不等于最长屏蔽时间。
新的时限论证必须重新确定目标IRQ/屏蔽域、足够宽且受控的时基、边界及最坏负载，
必要时用独立GPIO/逻辑分析仪交叉验证。
