# RTOS 性能测量参考与历史基准

本文保留测量口径、失效结论和必要历史数字，服务于后续可比较的新实验。当前实现
及复杂度以[设计手册](rtos_design.md)、[API契约](ai/README.md)为准，执行入口见
[HIL说明](../hil/README.md)。本页第 7 节记录 2026-11-11 的新实板测量。

原文9月基准早于10月生命周期、端口事务、出口ISB和全图继承修复，不能用于宣传当前
固件胜过其他RTOS。旧HIL批次及原始结果按用户要求清理；下列数字来自历史报告，
当前目录不能直接复核原始镜像/日志。曾提交原文可从Git历史查找，未入库资产不保证
恢复。旧PNG的数值还与旧表格不一致，已删除，不继续传播混合版本图表。

## 1. 测量对象与单位

目标板为NUCLEO-F446RE、168MHz、1kHz tick，DWT CYCCNT计cycle；1cycle约5.95238ns，
168000cycle恰为1ms。串口只输出结果，不放入目标测量区间。每个数字都需要源码、
有效配置、编译器/优化、链接输入、Flash设置、负载及测量边界，不能只附ELF摘要。

| 指标 | 实际含义 | 常见误读 |
|---|---|---|
| BM0 critical_pair | 一对enter/exit的批量平均 | 不是所有临界区最长屏蔽时间 |
| BM1 yield_switch | 同级任务yield切换区间的批量平均 | 不代表全部抢占/取消候选路径 |
| BM2 sem_roundtrip | 双任务各take/give及切换的一轮 | 不是单次sem API执行时间 |
| BM3 sem_wake_latency | give到高优任务恢复的区间 | 包含调度和异常切换 |
| BM4 queue_send_wake | 指定item大小的发送/唤醒区间 | 不能外推任意消息长度 |
| BM5 task_create_del | 指定栈/分配策略下创建删除 | 栈染料、堆形状、延期回收影响结果 |
| BM6 delay1_period | delay(1)的观察周期 | 不表示任意时刻都精确等待整1ms |
| BM7 isr_wake_latency | TIM6 ISR给令牌到任务恢复 | 不是串口到达延时或裸异常入口成本 |
| BM8 sem_give_before_pendsv | 高优任务已挂入信号量等待链，测量 give 返回之前的周期 | 不含 PendSV 搬运上下文及被唤醒任务执行 |

N=1可能表示已经计算的批量平均，先读夹具才能确定底层循环次数；不同历史阶段循环
次数也曾变化。此时min=max=avg不能解释成单次操作零抖动。实际样本的max也只是
观察最大值，不是WCET；DWT32位回绕、测量点扰动和首次采样都应处理。

`us_per_call`旧字段实际把1000000cycle转换为5952us，不是每次调用耗时。
给出的cycle→ns/us转换使用主频计算，避免把四舍五入系数当作精确时基。

## 2. 可比较实验的约束

- 同目标硬件/主频/tick、同编译器优化与链接选项、相同夹具和任务拓扑；
  对照内核的优先级方向不同，需要镜像语义，不能简单复用优先级数值。
- 检查所有参与链接对象及开关生效，强制重新编译受宏/快照影响的对象；新镜像不得
  用旧结果替代。CPU统计开关与名为perf的扩展夹具不是一回事。
- 区分扩展perf与普通bench，两者任务和布局不同。旧记录追加少量代码曾使BM2
  变化约6.9%，链接输入不同曾带来约11%差异；这些不是“±7%就算通过”的通用阈值。
  多复位/多布局/分段测量用于控制干扰，没有证据时不要归因某一条指令。
- 平均收益、样本最大值、资源成本和退步一并报告；重复整数输出不证明所有输入确定。
  当前响应deadline和可接受退化应由业务预先规定，不能套用历史百分比。

| yield | 191 | 142 |
| sem往返 | 1021 | 3203 |

## 4. 场景判读与已作废结论

| 场景 | 设计目的 | 历史问题/有效范围 |
|---|---|---|
| S1低持锁/中干扰/高抢锁 | PI头阻塞 | 创建次序未保证低优先持锁，20次高优试取都为空；原对比及优化归因作废 |
| S2的1/4/8等待者 | 成本随规模变化 | 一组give为340/339/339，只描述受测路径；位图定位后仍可能扫描，不能证明任意操作O(1) |
| S3混合管线 | 端到端/吞吐/控制 | 旧吞吐7895/7896items/s是受测镜像结果；不推出deadline保证 |
| S4周期长跑 | 2ms周期与抖动 | 10000样本含首次标定伪影；旧小于一个周期的最小值不是提前唤醒证明 |
| S5任务集 | 建立8任务×256word栈 | 不代表最大任务容量、长期分配或满负载栈安全 |

S1需要先确认低优实际持锁、高优真实等待和中优干扰，再计时。旧`control_deviation_cyc`
基准单调累加，错过周期后可保留固定相位偏移，已作废；用相邻实际周期并另验完成
response/deadline。S2的bad_threshold=0关闭超限统计，因此bad=0无时限含义。
观察“1/4/8平均相近”不能取代复杂度分析；当前入链、删除/重排、位图共享位清理
仍可能O(n)。旧“尾插O(1)”及“give完全与等待者解耦”的表述撤回。

旧内核text为21871B与21372B，也不能据此宣称当前更省Flash。旧按函数指令粗分yield
差距的逐项归因没有有效隔离实验，已撤回。旧D9最长屏蔽测量失败，见
[测试参考10.3](rtos_testing_report.md#103-已作废旧wcet测量方案)。

## 7. 2026-11-11 唤醒路径实测

NUCLEO-F446RE，168 MHz，默认 1 kHz Tick，GNU Arm GCC 11.3.1，BASEPRI，
断言开启。每个优化级的 A/B 除调度器选择实现外，使用相同代码、夹具和编译配置。
每边独立下载、复位三次，第二次交换顺序。表内为每次输出的平均周期的中位数，
本批次相同镜像三次结果一致。BM8 每轮采集 1,000 次真实信号量唤醒，夹具检查
高优任务确实在等待且 PendSV 选择正确。内层测量结束后才恢复外层临界区。

## 8. 实际 USART2 与 CNN 应用

同一 F446、同一帧流、同一应用和主机程序，只替换 `rtos_queue.c`。内核与模型均 O2，
模型关闭浮点收缩。下表取遥测窗口 8、推理窗口 4 的实际测量。ISR 周期按接收字节数
归一化，包含进入应用 IRQ 函数后的读寄存器、队列提交和计数，未计硬件异常入口／退出。

| 波特率／业务 | 平均 ISR 周期/字节，旧 → 新 | 主机响应/秒，旧 → 新 |
|---|---:|---:|
| 115200 遥测 | 552.03 → 497.32 | 256.15 → 256.15 |
| 115200 CNN | 551.26 → 498.47 | 5.52 → 5.52 |
| 921600 遥测 | 550.91 → 495.62 | 1645.47 → 1654.64 |
| 921600 CNN | 551.67 → 496.66 | 7.88 → 7.92 |

释放约 10% 的接收 ISR 周期，未观察到成比例的端到端吞吐变化。低速推理窗口接近
串口线速上限，高速窗口受 2044 字节 CNN 的处理时间及并发抢占约束。模型 O2→O3
同样负载中从 7.90 到 7.92 帧/秒，这一轮单次测量不足以证明可重复的端到端提速。
只替换队列的应用镜像 `text` 增加 148 字节，`data`、`bss` 不变。

解析和模型区间用 DWT 读数之差，可能包含抢占；主机延迟还包含 OS、ST-LINK 桥和
串口排队。各阶段指标不能简单相加为 CPU 总占用。归档保存实际串口字节及独立读数，
见[实板项目记录](logs/2026-11-11.md#uart-project)。

## 10. 互斥释放与批量超时的隔离实测

NUCLEO-F446RE，168 MHz、1 kHz Tick，GNU Arm GCC 11.3.1、BASEPRI、
断言开启。两项改动各自从同一工作树快照构建，修改前后使用同一夹具，
单独切换对应实现。O2 以旧、新、新、旧的顺序独立烧录四次；
O0、O3 各跑一对。表中为每轮平均的平均值，单位为 CPU 周期。

| 热路径与条件 | O0 旧 → 新 | O2 旧 → 新 | O3 旧 → 新 |
|---|---:|---:|---:|
| 最终释放空等待锁，注册 1 把 | 1404 → 242 | 826 → 112 | 781 → 112 |
| 最终释放空等待锁，注册 8 把 | 2403 → 241 | 1163 → 112 | 978 → 112 |
| 16 个信号量等待者同 tick 到期，注册 0 把锁 | 10059 → 8051 | 3030 → 2253 | 2977 → 2089 |
| 16 个信号量等待者同 tick 到期，注册 8 把锁 | 13913 → 11890 | 4142 → 3343 | 3761 → 2868 |
| 16 个队列等待者同 tick 到期，注册 0 把锁 | 9341 → 7333 | 2889 → 2112 | 2837 → 1949 |
| 16 个队列等待者同 tick 到期，注册 8 把锁 | 13195 → 11172 | 4001 → 3201 | 3621 → 2728 |

互斥夹具每组计时 1000 次 `give`，取锁、状态验证和串口输出在计时外。
只有被测锁由任务持有，其他注册锁空闲。另测实际竞争：放开无等待者的锁时，
另一把锁提供的继承保持，后续竞争交接及优先级恢复正确。O2 注册 8 把时，
所测释放路径约为 6.92 → 0.67 µs；有等待者的释放仍执行图求解，不能套用此结果。

Tick 夹具对每个「信号量或队列 × 0 或 8 把注册锁 × 1/4/8/16 个等待者」
组合测 48 次。通过链接包装测真实 SysTick 内的 `rtos_sched_tick`，
不计异常入口、端口外层临界区和随后 PendSV。每次核对任务在指定 tick 到期、
返回超时、等待链清空、接收缓冲未写及进入前后屏蔽状态一致。
8 把锁及 16 个信号量等待者的 O2 样本约为 24.65 → 19.90 µs。
旧注册表查找仍在外层保护内执行；节省的是重复临界区操作。

固定块池候选另测了 36 和 64 字节块、空闲链深度 0 和 31，每组 2048 次。
O2 的 64 字节块、深度 0 从 126.18 降到 119.13 周期；O0 的同组从 304.17
升至 325.15，36 字节同深度从 303.90 升至 333.13。候选已撤回，保留
测量夹具和结果；当前固定池仍执行有界空闲链扫描并拒绝重复归还。

本节只衡量明确的测量区间，不能推出整体吞吐增加的比例或最坏执行时间。
合入后的健壮性结果、归档位置与清理范围见
[每日记录](logs/2026-11-11.md#hotpath-optimization)。

### 14.1 降低分桶堆固定开销

少块和碎片用例都反复在最后一个活块之后拆分大空闲块，再归还并向右合并。旧版
O2 反汇编在这条路径多次读取并校验相同块头，重复计算源桶和目标桶，并执行摘链
与入链。右邻合并时还会反查已验证的当前块。相较于少块线性扫描，这些固定操作
占了更大比例。

最终实现按请求尺寸处理。精确桶命中使用专用摘除路径，直接核对块长、空闲位、物理
边界和链接。宽桶命中保留已校验的候选和桶号。同一临界区内，使用已知前驱长度核对
后继标签，并复用邻块读取。拆分或单侧合并后仍处于同一桶且原桶只有该节点时，直接
替换桶首。跨桶、桶内多节点和双邻合并继续预检所有相关节点，再执行修改。

本轮同板重测线性堆、冻结的旧分桶堆和最终分桶堆。每项各 256 次，DWT 覆盖完整 API
调用。32 B 用例在固定的小孔原址复用，4 KiB 用例从连续尾块拆分到另一大小桶。扩展
用例使用同一夹具在三个实现上启用 `HEAP_LATENCY_SIZE_CASES=1`。

| 场景 | 线性 O2 平均周期 | 旧分桶 O2 平均周期 | 最终分桶 O2 平均周期 |
|---|---:|---:|---:|
| 少块申请 160 B | 378 | 888 | 590 |
| 少块归还 | 174 | 1,012 | 569 |

### 14.2 按工作负载选择小表与尺寸桶

**工作负载采样**

在 F446 的冻结分桶镜像中，在堆临界区内按原始请求字节数、成功或失败以及操作前的物理
空闲块数计数。释放同时记录合并零、一个或两个邻块。启动和业务分别结算，业务结束时
遍历物理块交叉检查空闲块数量，并与内核成功计数对账。采样镜像用于统计调用形态，时延
来自无采样器的对照镜像。

| 30 秒 16 任务并发负载 | 148 B、4,096 B 各一次 | 0 / 0 | 0 | 65,287 条消息，221,551 次中断屏蔽检查 |

| 生命周期请求大小（B） | 成功 | 失败 | 用途 |
|---:|---:|---:|---|
| 148 | 147,086 | 0 | TCB，含三次申请到 TCB 后因栈不足回滚 |
| 512 | 123 | 3 | 压力任务栈 |
| 768 | 55,110 | 0 | 任务栈 |
| 896 | 55,110 | 0 | 任务栈 |

| 1,296 | 3 | 0 | 耗尽后的精确容量探针 |

三种采样镜像中，32 B 通用堆申请为零。该结论覆盖本工程在 F446 上运行的用例。
静态对象、ADC 固定池和 USB 专用存储不属于这个通用堆的分母。当前样本也没有连续采集
已部署客户固件的数据，因此不足以推断其他 MCU 应用的小块频率。

生命周期 294,178 次申请中，294,172 次申请前只有一个空闲块，占 99.998%。
294,172 次释放中，90.53% 在四个或更少空闲块时发生。旧版轨迹中，9,223 次释放在四个
空闲块时没有相邻空闲块，操作后空闲块数升到五个。只有 12 次无邻块释放发生在已有
5–8 个空闲块时。用容量为五的小表覆盖这个常见形态，第六个空闲块触发建桶，降到两块
时恢复小表。直方图记录的是旧版的操作前形态，无法还原新后端的切换次数或驻留时间。

桶按含头块长分类。小表按实际请求做等长优先和最小可用块选择。碎片多时保留原有的
16–120 B 精确块长及 128 B 起每个二次幂区间四档的分桶。实测 148 B TCB 对齐后占
160 B，对应 `[160,192)` 桶。512–1,024 B 栈请求对齐后跨多个宽桶。
当前样本支持减少这些请求常见路径的索引开销，缺乏改窄某一特定桶或预留 32 B 专用
块的证据。现有桶共享全部堆容量。

### 14.6 默认线性堆左合并试验

当前块头的 8 B 保存校验字和含头长度。从当前块可直接定位右邻，通用左邻定位需要前驱
长度，或空闲块尾标签加后继的前驱空闲标志。这两种方法可以沿用 8 B 块头，但会增加
拆分、分配和合并时的边界更新。已有可选分桶使用前驱标签。本轮实测使用只增加两个
32 位偏移的最近释放区间，覆盖升序连续释放，未实测通用尾标签方案。
[块边界标签的原始设计](https://gee.cs.oswego.edu/dl/html/malloc.html)

候选缓存一次成功释放后的物理块起止。缓存末端等于本次块起点时，才核对左块校验字、
长度和空闲标志。右边仍最多合一个块。每吸收一个头，空闲载荷账本加 8 B。分配提交前
检查改写的全部旧块是否覆盖缓存，并按需失效。释放按最终合并起点判断分配检查点是否
需要失效。缓存不参与分配的候选选择。

F446 同板 O2，168 MHz。混合两版重放相同请求、槽位及操作顺序，使用各自物理布局的
独立 first-fit 模型。O2 正反顺序复采的数值一致。

### 14.7 高频借还与按需失败诊断

现有 F446 实板画像覆盖的业务阶段中，ADC/DMA 采集用固定池，16 任务并发用例使用
静态工作任务，两者都没有通用堆调用。60 秒动态任务生命周期画像记录 294,172 次
成功申请和 6 次人为触发的失败，申请主要是 148 B TCB 和 512–1,024 B 栈。这组数据
用于说明任务管理成本。高频变长对象的单独基准使用 8–511 B 轮换尺寸、24 个
持续替换的工作槽和一个尾部探针，并交错释放。它是可重复的压力轨迹，生产数据尚不足以确定短寿命
变长对象的尺寸分布。

长寿命任务可在启动阶段创建，也可以由应用提供静态栈和 TCB。尺寸一致且同时在用块数
可估计的高频对象适合按业务配置固定块池。池的借出为 O(1)，归还仍有有界查重，最坏
随池块数增加。变长对象继续使用按地址 first-fit 的通用堆。

曾试验在每次完整失败后发布堆尾检查点。128 个隔离孔用例的重复失败从约 8,396 降至
134 周期，但 O2 混合成功申请从约 687 增至 724。分开成功返回后的候选仍使 O2 混合
申请约为 712、释放约为 218 周期。因此最终让现有 `rtos_heap_get_max_alloc()`
负责建立缓存。一次完整查询可记住确切最大连续块。只有原来没有内部检查点，或者
全堆最大连续块不超过旧前缀最大值时才发布。此时旧检查点无须保留，因为能从它开始
的申请均超过全堆最大值。任意有效释放会清除堆尾检查点，较小的可行请求重新从低
地址选择。

调用方在 `rtos_heap_alloc()` 返回 `NULL` 后可查最大连续载荷，再按业务允许的
最小尺寸选择缩小请求、分段、背压或丢弃。总空闲载荷与最大连续载荷各自是快照。总空闲
较高时仍可能没有合适连续段。原分配接口和返回值沿用，堆头为 8 B，复用原检查点字段。

### 14.15 当前堆与优化前纯线性堆的完整成本

主基线取自 11 月 12 日堆优化前的纯线性实现，与 Git HEAD `295ca5f` 中的堆文件
逐字节一致。两组共用当前其余内核、移植层、32 KiB 配置和相同夹具，输入只替换
`rtos_heap.c`。这份基线已具有与当前相同的正确账目、first-fit 和按需合并规则。
首次提交 `8ce7aeb` 的堆还含已修复的容量账目和极大请求问题，主对照采用修正后的
纯线性实现。各源码身份和差异清单保存在本地证据。

| 项目 | 优化前纯线性 | 当前实现 |
|---|---|---|
| 起扫位置 | 每次从堆首开始 | 检查点、精确前缀上限和全在用前缀 |
| 失败与最大容量 | 失败和查询各自扫描 | 完整扫描结果可供后续失败和查询复用 |
| 申请提交 | 按地址选块，按需合并 | 相同选块语义，减少重复校验与扫描 |
| 释放 | 直接定位，最多合并一个右邻，O(1) | 同为 O(1)，精简校验与提交 |
| 临界区 | 标准嵌套临界区 | 本次调用局部保存和恢复屏蔽值 |

#### 实际频次与加权平均

对业务窗口内互斥的成功申请、失败申请、释放及可选查询，保留各类 `N_i` 和
64 位原始周期总和 `S_i`。非空类别均值为 `S_i/N_i`，空类别权重为零，总体为

\[
\bar C_{\mathrm{API}}=\frac{\sum_i S_i}{\sum_i N_i}
=\sum_i\frac{N_i}{\sum_jN_j}\frac{S_i}{N_i}.
\]

计算使用原始整数总和，各类均值在最终展示时取小数。重试成功与失败分别进入成功和
失败主类。`SUBSTAT` 和重试链用于细分，属于上述主类中的子集。

业务例子采用确定性变长遥测缓冲区回放。创建 48 个长期 64 B 对象，交替归还一半
形成小孔。每场景 32 轮，每轮 96 帧，帧长循环为 64、128、192、256、384、512、
768、1024、1536 B。常规负载在约 16 帧在途时消费最早一帧。突发负载先积压
48 帧，此后每四个新帧主动消费一个，申请失败则释放最早帧并重试同一帧。
每轮排空报文，结束时归还所有长期对象。长期对象的创建、归还及促成恢复的释放
均计入统计。每个场景另有建场校准及终局归一验证，各一次最大块查询和整块申请、
释放在业务窗口外，并在输出中标记。模型所需的纯统计读取也位于计时区间外。

一次完整突发场景的 32 轮实测成功申请 3,120 次、释放 3,120 次、失败 1,247 次。两次 O2

#### 业界架构与适用场景

| 架构 | 优点 | 成本与适用条件 |
|---|---|---|
| 物理块线性扫描及检查点 | 固定额外状态，严格地址 first-fit，有效释放工作量固定，能够复用失败扫描 | 冷申请最坏随物理块数增长，依赖负载是否能复用检查点 |
| 移动起点或按需合并，例如 ThreadX byte pool | 可减少重复搜索，在实现允许时于扫描途中恢复中断 | 总扫描时间仍受碎片影响，起扫规则、等待及中断窗口各自不同 |
| 显式空闲链，例如 newlib-nano、FreeRTOS heap_4 | 申请只看空闲块，短链轻量，双向立即合并 | 按地址插入随空闲节点数增长。FreeRTOS heap_5 增加多区域组织 |
| 尺寸分离链表，例如 FreeRTOS heap_2、NuttX、dlmalloc | 小请求或常见尺寸可缩短搜索。选择策略可针对尺寸与分布 | 分桶或索引需要维护。heap_2 无合并，其他实现的合并与搜索上界各异 |
| 两级位图 TLSF、有限桶探测 Zephyr | 配置固定时分配器核心工作量有界，适合关注冷路径的变长负载 | 元数据、对齐、选块规则影响可用容量和常见路径。保护时长仍取决于实际接入 |
| 带子树最大值的区间树 | 可按地址剪枝、查最大空洞，平衡树可把搜索规模降到对数级 | 空闲区需要树节点与更新旋转。伸展树类实现侧重摊销成本 |
| Buddy 页分配 | 幂次阶的拆分和合并简单，适合页或对齐大块 | 非幂次请求有舍入损耗，阶数、回收和操作系统参与会改变延迟 |
| 单尺寸 slab 或固定块池 | 基本摘链、插链工作量固定，适合帧、描述符和控制对象 | 按尺寸预留，闲置类别不能直接借给其他类别。归还检测会增加开销 |
| 静态和单调 arena | 启动配置或同批生命周期，分配路径短，整批回收简单 | 任意顺序逐对象释放需由业务重新设计 |
| glibc、jemalloc、TCMalloc、mimalloc | 线程或 CPU 缓存、多个 arena 和回收策略针对并发与局部性 | 缓存驻留、跨线程归还和页调度改变内存与长尾，适合进程级比较 |
| Scudo、托管运行时 | 安全强化或自动生命周期管理 | 校验、隔离或 GC 带来独立的延迟和空间指标 |

Linux 内核的 buddy/SLUB、应用进程的 libc 分配器、ESP-IDF 的能力选择属于不同层。
能力选择用于把请求送往适当 RAM 区域。它可以与线性、分桶或其他底层机制组合。

### 14.18 首次碎片失败与真实定时器响应

F446 168 MHz、GCC 11.3.1、`-O2`、BASEPRI 0x50，所有对照保持 8 B 对齐。
Zephyr v4.2.0 `sys_heap` 用每尺寸桶的链表和非空位图找候选。在本配置中
起始桶最多试探三项，再由位图查更大桶。隔离小孔均不满足 80 B 请求时，
无需沿物理地址逐个验证这些孔。当前堆的释放会使相关检查点失效，首次失败
须验证物理块头，沿地址观察连续段长度，才能给严格 first-fit 或全堆诊断
提供结果。在 32 KiB 的原 80 B 业务失败夹具中，布局相当于 317 个待检查物理块头。
总空闲量大于请求时不能据它排除碎片，按需合并还能回收相邻块头。
[Zephyr v4.2.0 实现](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/v4.2.0/lib/heap/heap.c)

#### TIM5 相位扫描和周期干扰

TIM5 的 84 MHz CCR1 硬件比较产生真实 IRQ。原始镜像记录比较值到 ISR 首次读取
`CNT` 的差值。独立探针镜像以 168 MHz DWT 测量局部保护生效后的内部窗口，
