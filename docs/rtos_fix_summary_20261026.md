# RTOS 缺陷修复与提交汇总（2026-10-26）

本批汇总相对 `dc6f13a` 尚未入库的修复，涵盖 10 月 25 日的临界区问题及随后复杂并发测试发现的问题。更早已入库的调度、任务生命周期、内存、定时器和 USB 处理路径修复见 [10 月 13 日交付汇总](rtos_release_20261013.md)，不重复计为本批新发现。

## 已复现并修复的缺陷

| 编号 | 触发与原行为 | 修复后行为 | 原始复现与验证 |
|---|---|---|---|
| B01：临界区共享状态发布竞争 | 高优先级 IRQ 在保存槽位与嵌套计数更新之间重入，配对退出后 BASEPRI 仍可能停在 `0x50` | 保存原 PRIMASK，以短事务保护元数据发布和恢复；保留调用者更强的屏蔽，默认临界区主体仍允许高优先级硬件 ISR 抢占 | 旧版本确定性交错 36/600 失败；百万次配对发现 2680 次泄漏。见 [BASEPRI 报告](rtos_basepri_fix_20261025.md) |
| B02：阻塞 API 提前读取返回结果 | 空信号量没有释放者，100 次有限等待却全部返回初始 OK，TCB 实际结果为 TIMEOUT | 公共临界区出口恢复屏蔽后执行 ISB，使已允许的 PendSV 先于后续结果读取被识别 | 最终跨配置检查 6000 次五类真实阻塞，未出现假成功或提前返回；见同一报告 |
| B03：锁依赖的继承与撤销传播不完整 | 高优先级等待者进入、离开或改优先级后，深层持锁者没有正确更新；循环依赖也可能遗留旧捐赠 | 从基础优先级有界求解全部锁依赖，统一发布有效优先级；所有权移交后重新计算并刷新调度候选 | 2/3/6 层锁链 801 PASS / 109 FAIL → 910 / 0；有限循环及容量边界另有专项覆盖 |
| B04：对象预检与销毁之间的竞争窗口 | API 在临界区外读到 initialized，合法 ISR 随后 deinit，原调用仍读改失效对象或登记等待 | sem、queue、event、mutex 在首次临界区内再次检查初始化状态；queue 重试入口同样复检 | 真实 TIM7 ISR 的 80 个窗口用例，8 PASS / 72 FAIL → 80 / 0 |
| B05：互斥锁递归计数回绕 | 已持锁任务的递归计数为 UINT32_MAX 时，再次 take 返回成功并将计数变为 0 | 返回 ERR_OVERFLOW，所有权和计数保持不变；give 拒绝无效的零递归状态 | 边界注入明确标记；包含移交和有限环的同一套检查，84 PASS / 3 FAIL → 87 / 0，其中一个失败属于 B03 |

B03～B05 的构造、失败现场、修改方案和逐镜像索引见 [复杂并发报告](rtos_adversarial_20261026.md)。断言失败数不等于独立 BUG 数，也不等于独立业务场景数。

此外补齐/前移 heap、perf、USB 的 27 处 ISR 优先级检查，增加临界区计数下溢/溢出检查，并保留关闭断言时的非法计数状态。这组防御检查加强契约诊断，不把优先级 0～4 调用对象 API 解释为合法用法；关闭断言也不放宽契约。

## 最终验证

平台为 NUCLEO-F446RE、168 MHz、1 kHz tick，原 ST-LINK/SWD 与 COM3/115200 接口。

| 验证 | 当前合并修复版本的实际结果 |
|---|---|
| 复杂并发配置矩阵 | 5 套夹具 × BASEPRI/PRIMASK × 断言开/关 × O0/O2/O3，共 60 个镜像、35,232 项检查，通过 |
| 既有端口回归 | 74 个镜像；包括 7200 个确定性交错、1200 万次临界区配对、6000 次真实阻塞及优先级/非法嵌套边界，通过 |
| 功能与上下文 | audit 117/0；selftest 432/0、10 INFO；boundary 103/0；LC 24/0、PC 22/0 |
| 业务压力 | 队列容量 1/8/32、不同 seed 的三轮 30 秒测试；另有 16 worker、三层 IRQ 的 900 秒测试，最终均为 165/0、worker_errors=0 |
| 900 秒消息与屏蔽守恒 | 成功接纳并消费 1,973,927 条消息；6,658,682 次线程安全点检查、屏蔽泄漏 0；堆状态恢复 |
| 负向对照 | 单包 checksum 损坏被检出，出现预期失败并以非零状态结束，不记为正常通过 |
| 严格编译 | 8 个相关 C 文件 × 12 配置，加 CM7 port 仅编译检查，共 97 次零警告；CM7 硬件未测 |
| 独立证据复核 | [最新校验摘要](../hil/adversarial_20261025/verification_summary.json)：strict PASS，errors=[]、pending=[] |

完整测试固件另有 main.c 既有的 25 条未使用演示声明警告，不能将相关翻译单元的严格编译结果说成整个工程零警告。新增夹具使用 `-Wextra -Werror`，矩阵执行器拒绝其它诊断。

## 保留状态与复现入口

- `Core/Src/main.c` 没有修改，板上已恢复并验证日常固件；内核修复保留，没有改变 TCB/PendSV 栈帧 ABI。
- 新测试已纳入 `hil/repro_all.ps1 -Only adversarial`；端口矩阵为 `-Only port`。执行会重新烧录固件，具体流程见 [HIL 说明](../hil/README.md)。
- 已清理 477 个中间文件、14,676,857 B，未删除 tracked 文件；故障基线、原始日志和必要身份记录保留。
- Git 发布源码、测试脚本、文本证据与文档。本机保留的 ELF、栈记录和 Debug 构建输入不随 Git 发布；换行转换和本机路径也影响精确字节身份，见 HIL 发布范围说明。

优先级继承不解决死锁；全图重算增加临界区工作与栈开销，默认配置静态图函数帧为 112～160 B，不是完整调用链或 WCET 上界。对象复检不能使已释放或被复用的存储继续有效。本轮没有验证物理 USB 主机枚举和数据传输；有限回归也不能证明不存在其它 BUG。
