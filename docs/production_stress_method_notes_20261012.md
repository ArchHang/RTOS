# 生产负载综合压力测试的方法依据

本文是测试设计与审查说明。硬件执行结果、固件身份、运行时长和最终判据以本轮综合测试报告及原始 HIL 日志为准；本文不代表任何场景已经通过。

## 成熟方案中的可用方法

FreeRTOS 的 IntQueue 测试让不同优先级任务与两路嵌套中断共同访问队列，检查每条消息的接收记录以发现重复和遗漏，并检查高优先级等待者的优先获取行为。可借鉴的是可核对的消息身份和实际并发覆盖条件。自研内核的返回值和调度语义仍按本项目实现确定。[FreeRTOS IntQueue 源码](https://github.com/FreeRTOS/FreeRTOS/blob/main/FreeRTOS/Demo/Common/Minimal/IntQueue.c)

FreeRTOS 的 comprehensive demo 将队列、信号量、事件、动态优先级及任务生命周期测试放在同一运行系统，由独立检查任务定期检查各子系统是否仍有进展。健康任务不能只检查总计数：每个受测角色都应有单独进度和错误锁存。[FreeRTOS comprehensive demo](https://github.com/FreeRTOS/FreeRTOS/blob/main/FreeRTOS/Demo/Posix_GCC/main_full.c)

Zephyr Ztress 使用不同优先级线程和定时器上下文，加入随机等待，记录执行和抢占次数，并设置次数与超时条件。本项目采用可重放种子、周期进度、最低覆盖次数和限时退出；不把运行一段时间本身视为成功。[Zephyr 测试框架与 Ztress](https://docs.zephyrproject.org/latest/develop/test/ztest.html#stress-test-framework)、[Ztress 官方头文件源码](https://docs.zephyrproject.org/latest/doxygen/html/ztress_8h_source.html)

## 贴合工业控制和采集系统的模型

建议将负载定义为“采集、传输、处理、控制、记录”流水线：多个采集任务和硬件定时器 ISR 产生带来源、序号和校验值的记录；多个处理任务竞争同一队列；有限 DMA 或计算资源用计数信号量管理；就绪和报警状态用 event 通知；共享配置及统计用互斥锁保护。高优先级控制任务定时运行，低优先级维护任务检查资源和恢复行为。

生产上的故障压力应有显式阶段：正常负载、突发过载、停止部分处理、恢复处理、停止生产并排空、资源清理。过载时出现队列满或有限超时属于设计行为，但必须计入拒收数量。无法解释的丢失、重复、数据损坏或资源未恢复属于失败。

16 个业务任务应覆盖十几个不同优先级。所有业务角色都有独立进度；仅观测总吞吐不能证明低优先级任务获得运行机会。压力固件关闭应用 USB 任务以给夹具留出 RAM，这限定了本测试的并发范围，不代表物理 USB 压力验证。

## 必须从自研内核语义导出的判据

1. **队列**：只有返回 RTOS_OK 的发送才属于接纳消息。发送超时或队列满不能计入已接纳记录。排空后应满足接纳数等于完成数；按来源和序号检查消息身份，再检查内容校验值。多消费者完成顺序可能不同于出队顺序，不能仅靠完成时间要求严格单调。
2. **队列等待优先级**：受控阶段先确认不同优先级接收者或发送者确实已经阻塞，再释放单个消息或槽位，检查最高优先级等待者的身份。自然负载下未观察到同时阻塞不能算这一判据通过。
3. **计数信号量**：资源令牌数加在用资源数应恒等于容量，持有成功后才允许释放。生产令牌型同步还应检查成功 give 与成功 take 和最终剩余 count 的守恒。ISR give 的 overflow 必须记录，不能忽略后宣称无损。
4. **事件标志**：本项目 rtos_event_set 按优先级遍历，并在每个满足条件的等待者上立即执行 CLEAR_ON_EXIT。相同位的多个消费式等待者不一定全部成功，不能照搬其他内核广播后统一清位的语义。建议用不清位 readiness 广播、互不重叠的消费位，另设受控同位竞争阶段。检查 ANY/ALL 必须检查所需位是否真正满足，而不是仅检查返回值非零；超时也会返回当前位快照。
5. **多中断**：TIM6、TIM7 均使用允许内核 API 的 NVIC 优先级，阻塞型接口在 ISR 只用 RTOS_NO_WAIT，互斥锁和任务删除不在 ISR 调用。嵌套覆盖必须由真实 ISR 活跃深度计数确认。等待更高优先级 ISR 的覆盖握手不能置于屏蔽该 ISR 的临界区。
6. **恢复与清理**：停止中断生产在 IPC 对象销毁之前；停止标志须经同步发布；处理端排空后才终止。即使超时失败也需有有界清理路径，不能让前一轮待处理数据污染下一轮。
7. **测试器可信度**：负向对照可只损坏一条测试消息的校验值，在同一真实板载判据上产生明确失败。不得让负向对照预置失败计数；需要由正常接收检查发现损坏，证明日志解析器也拒绝该运行。

## 资源、观察和证据约束

STM32F446 工程链接脚本仅有 128 KiB RAM。日常固件 bss 已为 125952 字节，新增静态栈、队列存储和消息位图必须以压力固件的 map/size 实际检查，不能只依据关闭 USB 的假设。优先采用固定容量存储，避免夹具的动态内存干扰受测对象。

任务性能注册表容量为 18，而 16 个业务任务加 controller、idle、timer 可达 19 个。保持生产配置时，不宜以 perf 注册表条目数或其遍历结果作为所有业务任务都受检查的证明。夹具可直接持有其 TCB，并分别校验栈余量及活跃状态；日志要注明这一范围。

共享可变计数的读改写与多字段快照必须使用临界区或互斥锁。volatile 不能代替同步。硬件 IRQ 之间相互抢占的计数也适用这一要求。

HIL 应在打开串口后执行 SWD 下载、校验和复位，避免丢失启动输出。每次运行保留 ELF 的 SHA256、源码身份、参数种子、编译日志、下载校验、串口日志和结束标志。未知输出、缺失结束标志、未达到覆盖下限、任一锁存错误或清理失败均不能被归为通过。

短运行用于检出实现和夹具错误；多个种子、队列容量 1/8/32 及延长运行用于改变交错和背压。报告应给出实际运行时间、消息数和覆盖值，不能把有限压力测试表述为绝无竞态、完整 WCET 证明或正式工业认证。
