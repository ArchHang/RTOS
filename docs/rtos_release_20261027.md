最终诊断验证包括：

- 12 个屏蔽/断言/优化组合，每个 472 项实板功能检查；最小容量、关闭分支和等工作量基准，
  新夹具合计 6067 项通过。

- 实际 UDF 后通过 SWD 读取 9 条连续提交记录及两条完整 marker；RAM/串口 PC 和
  目标地址的 `0xDE00` 指令一致。栈容量 4096、剩余 4056、当前帧使用 40 字节。
- 48 个记录接受器负例和 10 个 SWD 接受器负例通过；原始失败尝试保留，没有改写为 PASS。

## 性能、RAM 与安全边界

完整诊断的 O2 高频阻塞交换耗时增加 46.14%–70.87%，O3 增加 52.61%–71.16%。
这些是含循环、API、调度和中断干扰的等工作量样本，不是整机吞吐变化或 WCET。
完整默认模块静态预算为 2604 字节；基准/日常镜像裁剪后的 RAM 净增加为 2596 字节。
因此 Debug 按需开启，Release 真正编译关闭；运行时 freeze 不等于编译关闭。

诊断关闭、断言关闭、O2/CHANNEL=1 下，原有 17/17 单元的可装载内容、布局及重定位目标
与诊断加入前一致，关闭模块无静态状态。最终日常 OFF 镜像没有诊断函数、helper 或记录缓冲；
恢复权威模板后的可装载镜像与已验证 daily OFF 镜像一致。

共享通道防护覆盖合法 API 的票据与资源协议，不能撤销裸 C 指针或提供 MPU 隔离。
诊断解释只覆盖仍可见的等待 episode，历史缺失返回 UNKNOWN。致命故障冻结仅用于最终停机，
不提供 NMI 周期监督、跨复位持久化或通用死锁判定。新业务健康监督的边界见
[运行正确性监督提案](rtos_runtime_supervision_proposal.md)。
